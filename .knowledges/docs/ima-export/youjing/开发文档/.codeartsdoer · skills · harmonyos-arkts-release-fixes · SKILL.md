# HarmonyOS ArkTS 发布前修复与商业化改造

## 适用场景

- 项目从开发期转向上架盈利，需要修发布前红线（数据损坏、合规、安全）。
- 需要把直连 LLM 的端侧 Key 改为 BFF 中转 + 设备票据。
- 需要加权益系统（订阅/通行证/免费额度）与付费墙。
- RDB 迁移链有 `executeSql` 未 `await` 或 CREATE/ALTER 重复列的 bug。

## 执行顺序（不要跳）

1. **先写契约文档**（`Docs/商业化方案.md` 或同类）：DDL、接口 Schema、错误码表、端侧改造清单、落地顺序。固化方案再动代码，避免边写边改口径。
2. **P0 修复**（不依赖后端，可立即做）：RDB 迁移链 + 隐私闸门。
3. **P1 基础设施**（后端就绪后接线）：ApiConfig 改造 + LlmClient 鉴权/幂等 + ErrorCode 云端区段 + EntitlementStore。
4. **P2 UI 层**：PricingPage + GeneratingPage 402 分支 + 导出付费墙。
5. **验证一致性**：grep 旧字段引用、确认 await 覆盖、确认路由注册。

每步用 TodoWrite 跟踪状态。

## ArkData RDB 迁移纪律

### executeSql 必须 await

`relationalStore.RdbStore.executeSql()` 是 Promise 版本。不 await 会导致：
- DDL 异步浮动，`commit()` 可能先于 DDL 完成；
- 异常不进入 catch → 迁移半途失败被静默吞掉；
- `store.version = DB_VERSION` 照写 → 永不再重试。

**修复**：迁移函数中每一处 `store.executeSql(...)` 都改为 `await store.executeSql(...)`。全仓 grep `store\.executeSql` 确认 0 处遗漏（含 DAO 层的 `executeSql`）。

### CREATE TABLE 不能含后续 ALTER 的列

累积式迁移（`if (oldVersion < N)`）要求新建库（`oldVersion === 0`）先 CREATE 基线表，再逐级 ALTER。如果 CREATE TABLE 已含某列，而后续 `oldVersion < N` 又 `ALTER ADD` 同名列 → 新建库必撞 duplicate column。

**修复**：把 CREATE TABLE 中与后续 ALTER 重复的列去掉，让累积式迁移统一处理。典型重复列：
- `user_id`（CREATE TRIP 已含 + v2 ALTER ADD）
- `confidence`（CREATE SPOT 已含 + v5 ALTER ADD）
- `time`（CREATE MEAL 已含 + v6 ALTER ADD）

### version 只在所有 DDL 成功后写

```typescript
// 所有 await store.executeSql(...) 完成后
store.version = DB_VERSION;
await store.commit();
```

如果中间某步失败 → catch → rollBack → 不写 version → 下次启动会重试迁移。

### 加新列的迁移步骤

1. `DB_VERSION` +1；
2. 加 `SQL_VN_ADD_XXX` 常量；
3. 在 `migrate()` 加 `if (oldVersion < N) { await store.executeSql(SQL_VN_ADD_XXX); }`；
4. 更新文件头注释中的版本号（如"表结构（v8）"→"（v10）"）。

## 隐私同意逻辑闸门

### 问题模式

只在 `aboutToAppear` 弹窗做视觉遮挡，但 `build()` 已构建完整 `mainTabs`，且 `AccountStore.init`/DAO 在同意前已执行 → 合规事故。

### 修复模式

1. **`@StorageProp(CONSENT_AGREED_KEY)` 作为 `build()` 第一道分支**：
   ```typescript
   build() {
     Column() {
       if (this.consentAgreed !== '1') {
         Blank()  // 同意前什么都不画
       } else if (this.authState === '') {
         Blank()  // 登录态水合中
       } else if (this.authState !== 'huawei' && !this.guestChosen) {
         LoginView({ ... })
       } else {
         this.mainTabs()
       }
     }
   }
   ```

2. **数据读取移到同意后**：把 `AccountStore.init` + DAO 调用抽成 `bootstrap()`，只在 `ConsentStore.init` 返回 `agreed=true` 时执行；`onAgree` 回调里也调 `bootstrap()`。

3. **确认 `ConsentStore.init` 会写 AppStorage**：`@StorageProp` 的值由 `ConsentStore.init` 在异步完成后 `AppStorage.setOrCreate(CONSENT_AGREED_KEY, ...)` 设置。验证 `ConsentStore.init` 的实现确实有这一行。

### 死变量检测

`@StorageProp(CONSENT_AGREED_KEY) consentAgreed` 声明后如果从未在 `build()` 中使用 → 死变量。修复方式是把它作为 `build()` 的第一道分支条件。

## API Key 出端改造

### ApiConfig 改造

- 删 `BASE_URL`（直连 LLM 地址）和 `API_KEY`（明文 Key）；
- 加 `BFF_BASE_URL`（空串占位，上架前填入）和 `DEVICE_TOKEN`（设备票据）；
- `LLM_CHAT_ENDPOINT` 改为 BFF 端点路径（如 `/v1/trip/generate`）；
- 保留 `LLM_MODEL`/`LLM_THINKING_DISABLED`/`LLM_MAX_TOKENS` 等（BFF 可覆盖）。

### LlmClient 改造

1. **鉴权头**：`Authorization: Bearer ${DeviceTokenStore.getToken()}` 替代 `Bearer ${ApiConfig.API_KEY}`。token 为空时不带鉴权头（仅告警）。
2. **幂等键**：`generateTrip` 生成一次 `idempotencyKey`，重试时复用同一个 key（不是每次新请求）：
   ```typescript
   const idempotencyKey: string = `${Date.now()}-${Math.random().toString(36).slice(2)}`;
   for (let attempt = 0; attempt < 2; attempt++) {
     raw = await t.complete(idempotencyKey);
   }
   ```
3. **错误码区分**：
   - 401 → `CLOUD_TOKEN_INVALID`（重新激活）
   - 402 → `CLOUD_QUOTA_EXHAUSTED`（跳 PricingPage）
   - 429 → `CLOUD_RATE_LIMITED`（提示稍后重试）
   - 409 → `CLOUD_IDEMPOTENCY_CONFLICT`（不应重试）
   - 其他非 2xx → `NETWORK_REQUEST_FAILED`
4. **401 自动重新激活**：在 `generateTrip` 的 catch 块中检测 `CLOUD_TOKEN_INVALID`，仅在第一次失败（`attempt === 0`）且 `context` 可用时调 `DeviceActivator.reactivate(context)`，第二次重试将使用新 token。`generateTrip` 新增 `context?: common.Context` 和 `passId?: string` 可选参数，由调用方（GeneratingPage）传入。
5. **LlmTransport 接口**：`complete(idempotencyKey?: string): Promise<string>` — 两个 transport 都从构造器获取 PlanParams/Spot[]/Area，不再通过 `complete()` 参数传 `LlmRequest`。MockLlmTransport 和 HttpLlmTransport 构造器签名一致：`(params, spots, area, passId?)`。

### HttpLlmTransport BFF 契约对齐

端侧不再构建 OpenAI chat/completions 格式（messages + model + response_format），改为发送**业务参数**让 BFF 内部构建 prompt、注入 Key、扣减配额、转发 LLM。

**请求体**（对应 BFF `/v1/trip/generate` 期望的 `req.body`）：
```typescript
body['destination'] = params.basic.destination;
body['startDate'] = params.basic.startDate;
body['endDate'] = params.basic.endDate;
body['people'] = params.basic.people;
body['budget'] = params.basic.budget;
body['style'] = params.style;
body['selectedArea'] = area.name;              // 区域名，不是 areaId
body['selectedSpots'] = spotNames;             // 景点名数组，不是 spotId
body['passId'] = passId;                       // localTripId（有通行证时才发）
body['freeTier'] = !EntitlementStore.hasSubscription();
```

**关键映射**：端侧 `SelectedSpot.spotId` 需通过 `spots.find()` 映射为 `Spot.name` 发给 BFF，因为 BFF 用景点名构建 prompt。

**响应解析**：BFF 返回 `{ trip, quota }` 格式（不是 chat/completions 的 choices 信封）：
- `trip`：已解析的 JSON 对象 → `JSON.stringify(env.trip)` 后交 TripParser 守卫；
- `quota`：权益快照（`source`/`remainingToday`/`giftRemaining`/`passes`）→ 合并现有缓存中 `subscription`/`dailyCap` 后调 `EntitlementStore.update()`。
- BFF 的 `remainingToday` 字段实为 `usedToday`（命名误导但以 BFF 代码为准）。

### ErrorCode 云端区段

在现有区段后追加 6xxx：
```
6001 CLOUD_TOKEN_INVALID
6002 CLOUD_QUOTA_EXHAUSTED
6003 CLOUD_RATE_LIMITED
6004 CLOUD_IDEMPOTENCY_CONFLICT
6005 CLOUD_PASS_NOT_FOUND
6006 CLOUD_IAP_VERIFY_FAILED
```

## 设备激活流程（DeviceTokenStore + DeviceActivator）

### DeviceTokenStore 模式

与 ConsentStore/EntitlementStore 同一 preferences Store 模式：
- `deviceId`：端上首次生成 UUID 并持久化，之后不变（`ensureDeviceId()`）；
- `deviceToken`：BFF `/v1/device/activate` 返回的 Bearer 票据，存 preferences；
- `init(context)` 恢复、`getToken()` 同步读、`saveToken()` 写+持久化、`clear()` 清票据（保留 deviceId）。

### DeviceActivator 模式

- `activate(context)`：BFF_BASE_URL 为空时跳过（开发期 Mock）；否则 POST `/v1/device/activate`，传 `{ deviceId, unionId }`，返回 `{ deviceToken, entitlement }` → 分别写入 DeviceTokenStore 和 EntitlementStore；
- `reactivate(context)`：票据失效（BFF 401/6001）时先 `clear()` 再 `activate()`；
- 激活失败不阻断主流程：用户仍可进入主界面，首次请求 BFF 时拿到 401 再触发重新激活；
- 用 `activating` 静态标志防止并发重复调用。

### ApiConfig 删 DEVICE_TOKEN

`DEVICE_TOKEN` 从 ApiConfig 移到运行时 DeviceTokenStore。LlmClient 的 Authorization 头改为：
```typescript
const token: string = DeviceTokenStore.getToken();
if (token.length > 0) {
  headers['Authorization'] = `Bearer ${token}`;
}
```

### bootstrap() 里的激活顺序

```typescript
private bootstrap(ctx: common.Context): void {
  DeviceTokenStore.init(ctx)
    .then((): Promise<boolean> => DeviceActivator.activate(ctx))
    .catch((): void => {});
  EntitlementStore.init(ctx).catch((): void => {});
  AccountStore.init(ctx)
    .then((): Promise<TripSummary[]> => TripDao.listSummaries(ctx))
    .then((rows: TripSummary[]): void => { ... })
    .catch((): void => {});
}
```

DeviceTokenStore.init 必须先于 DeviceActivator.activate（后者依赖前者恢复 deviceId）。

## 权益系统（EntitlementStore）

- preferences 分片缓存 + 5 分钟 TTL；
- `canExport(tripId)`：订阅有效或该行程有通行证 → 放行；
- `canGenerate()`：订阅日额度未满或赠送次数 > 0 → 放行；
- 离线时用缓存判定，缓存过期默认拒绝（保守策略）。

## 导出付费墙接入

生成与查看免费，**导出收费**（ICS/PDF/海报）。用户在"行程做完要落地"时付费意愿最高。

### 接入点

- **SharePage.exportIcs()**：ICS 导出前加 `EntitlementStore.canExport(tripId)` 判定，无权益时 `this.pathStack.pushPath({ name: 'Pricing' })`；
- **TripReviewPage.sharePoster()**：海报分享前加同样判定；
- **文本分享（shareText）不加付费墙**：分享行程文本是免费功能，只有 ICS/PDF/海报导出收费。

### NavDestination pathStack 获取

SharePage 等需要导航跳转的 NavDestination 页面，需在 HdsNavDestination 上加 `.onReady()` 获取 pathStack：
```typescript
private pathStack: NavPathStack = APP_NAV;

// 在 HdsNavDestination 链上：
.onReady((ctx: NavDestinationContext): void => {
  this.pathStack = ctx.pathStack;
})
```
不加 `.onReady()` 时 pathStack 保持 APP_NAV 默认值（也能用，但多 tab 场景下可能跳错栈）。

## IAP Kit 接线（@kit.IAPKit）

### 核心 API

- `iap.createPurchase(context, parameter)` — 发起购买，返回 `CreatePurchaseResult`（含 `purchaseData.purchaseToken`）；
- `iap.queryPurchases(context, parameter)` — 查询已购商品（恢复购买用），`queryType: iap.PurchaseQueryType.CURRENT_ENTITLEMENT`；
- `iap.finishPurchase(context, parameter)` — 确认发货，参数含 `{ productType, purchaseToken, purchaseOrderId }`。

### 产品类型映射

| 商品 | ProductType | productId |
|---|---|---|
| 行程通行证 9.9 元 | `NONCONSUMABLE` | `youjing_pass` |
| 月订阅 19.9 元 | `AUTORENEWABLE` | `youjing_sub_monthly` |
| 年订阅 98 元 | `AUTORENEWABLE` | `youjing_sub_yearly` |

### 购买流程（三步链路）

1. `iap.createPurchase()` → 拿到 `purchaseToken`；
2. `verifyWithBff()` → POST BFF `/v1/iap/verify`，BFF 返回 `{ verified, entitlement, passId }` → 写入 EntitlementStore；
3. `iap.finishPurchase()` → 确认发货（BFF 校验成功后才调）。

BFF_BASE_URL 为空时跳过校验（开发期），仅日志记录。

### 恢复购买

`iap.queryPurchases()` 分别查 NONCONSUMABLE 和 AUTORENEWABLE（`CURRENT_ENTITLEMENT`），逐条向 BFF 校验。换设备/重装后恢复权益。

### 用户取消处理

`iap.createPurchase` 抛错时 `BusinessError.code === 1001860000`（`USER_CANCELED`）→ 不当错误处理，返回"用户取消购买"。

### PricingPage 按钮接线

- 通行证按钮 → `IapStore.purchasePass(ctx, localTripId)`（localTripId 从 AppStorage activeTripId 读）；
- 月订阅/年订阅按钮 → `IapStore.purchaseSubscription(ctx, productId)`；
- 恢复购买按钮 → `IapStore.restorePurchases(ctx)`；
- 购买中按钮文案改为"处理中…"（`@State purchasing` 标志）。

## 定价设计原则

- 免费额度**终身制**（注册赠 N 次），不按月重置——低频场景下月重置会覆盖大部分真实需求，导致永不付费且成本线性增长。
- 订阅次数上限是**防滥用闸门**，不是卖点；卖点是能力差异（多天、导出、优先队列）。
- 行程通行证（单行程无限重排 + 导出）是主推产品，月订阅面向高频用户。

## BFF 后端项目结构

Express + better-sqlite3 + jsonwebtoken，本地可跑、上架时可迁移到华为云函数 + CloudDB。

### 目录结构

```
bff/
  package.json          # type: module, deps: express/better-sqlite3/jsonwebtoken/uuid/dotenv
  .env.example          # DEEPSEEK_API_KEY, JWT_SECRET, PORT, LLM_MODEL, LLM_BASE_URL
  src/
    index.js            # Express 入口，路由挂载 + 错误处理
    db.js               # SQLite 初始化 + 6 张表 DDL（与契约文档同源）
    middleware/
      auth.js           # JWT Bearer 票据验证 + issueToken()
      idempotency.js    # Idempotency-Key 幂等检查（pending/succeeded/failed 三态）
    services/
      quota.js          # 权益查询 + 预扣/结算/回滚 + 扣减顺序（订阅→通行证→赠送）
      llm.js            # DeepSeek API 代理（注入 Key、转发请求、返回 content + usage）
      iap.js            # IAP 服务端校验（占位，待接华为 IAP 校验 API）
    routes/
      device.js         # POST /v1/device/activate
      entitlement.js    # GET /v1/entitlement
      trip.js           # POST /v1/trip/generate
      iap.js            # POST /v1/iap/verify + POST /v1/iap/notify
```

### 关键设计

- **DDL 与契约文档同源**：`db.js` 的 CREATE TABLE 语句直接对应 `Docs/商业化方案.md` §3 的 DDL，字段名/类型/索引一一对应。
- **幂等中间件**：`Idempotency-Key` 头 → 查 `trip_request` 表 → succeeded 返回缓存结果、pending 返回 409、failed 返回 409（要求换新键重试）。
- **配额三态**：`reserveQuota`（reserved）→ `commitQuota`（committed，扣）或 `releaseQuota`（released，不扣）。LLM 上游失败时 release，成功时 commit。
- **扣减顺序**：`determineQuotaSource()` 按订阅日额度 → 通行证 → 赠送次数 依次判定。
- **JWT 票据**：`issueToken(accountId, deviceId)` 签发 30 天有效期；`authMiddleware` 验证 Bearer 头并注入 `req.accountId`。
- **设备激活**：匿名设备用 `anon-${deviceId}` 作 union_id 创建账号；有 unionId 时按 union_id 查/建账号并更新 device_id。

### IAP 校验路由

- `POST /v1/iap/verify`：接收 `{ purchaseToken, productType, localTripId }`，调 `verifyPurchase()` → 写 `order`/`subscription`/`trip_pass` 表 → 返回 `{ verified, entitlement, passId }`；
- `POST /v1/iap/notify`：华为服务端 webhook 占位（必须验签，待接华为 IAP 通知 API）。

## 改动后一致性验证

1. `grep "ApiConfig\.BASE_URL\|ApiConfig\.API_KEY"` → 0 命中（旧字段已全部替换）。
2. `grep "store\.executeSql" | grep -v await` → 0 命中（全部 await）。
3. 新页面注册到 `AppRouter.routerMap`。
4. 新文件的头注释与现有风格一致（路径前缀、TAG 常量、契约说明）。
5. `@StorageProp` 闸门变量的初始值与 `ConsentStore` 写入值匹配（`'0'` vs `'1'`）。

## 常见陷阱

- 把 `consentAgreed` 声明为 `@StorageProp` 但不在 `build()` 中使用 → 死变量，闸门形同虚设。
- `aboutToAppear` 里在 `ConsentStore.init` 之外并行调 `AccountStore.init` → 同意前已读取数据。
- 重试时生成新的 `idempotencyKey` → 弱网重复扣费。
- `executeSql` 不 await 但 `commit` await → commit 先于 DDL 完成，迁移静默失败。
- CREATE TABLE 含后续 ALTER 的列 → 新建库 duplicate column（当前因不 await 才没抛，一旦修复 await 会立刻暴露）。
- 新建页面忘记注册到 `AppRouter.routerMap` → 导航到 `ComingSoonPage`。
- ArkTS 严格模式不允许 `undefined` 作为属性值（如 `.border(condition ? {...} : undefined)`）→ 改用 `.borderWidth(condition ? 2 : 0)`。

## ArkTS 严格模式编译错误修复

商业化改造涉及大量类型变更，构建时常见的 ArkTS 编译错误及修复方式：

### `arkts-no-obj-literals-as-types`：对象字面量不能作为类型声明

ArkTS 不允许内联对象类型 `{ status: string; periodEnd: string }` 作为类型标注，必须定义具名 interface。

```typescript
// ❌ 编译失败
subscription: { status: string; periodEnd: string } | null;
const sub: { status: string; periodEnd: string } | null = cached.subscription;

// ✅ 修复：定义具名 interface
interface SubscriptionInfo {
  status: string;
  periodEnd: string;
}
subscription: SubscriptionInfo | null;
const sub: SubscriptionInfo | null = cached.subscription;
```

典型触发场景：EntitlementStore 的 `subscription` 字段、任何从 BFF 响应映射的内联类型。

### `arkts-limited-throw`：throw 只能抛 Error 类型

ArkTS 的 `catch (err)` 中 `err` 是 `unknown` 类型，直接 `throw err` 会编译失败。

```typescript
// ❌ 编译失败
catch (err) {
  throw err;
}

// ✅ 修复：显式断言为 Error
catch (err) {
  throw err as Error;
}
```

典型触发场景：CalendarSync 的 try-catch 回滚逻辑中重新抛出异常。

### SDK 模块未导出类型：定义本地 interface + `as` 断言

`@kit.IAPKit` 等模块可能不导出某些类型（如 `iap.PurchaseData`），编译报 `'iap' has no exported member named 'PurchaseData'`。

```typescript
// ❌ 编译失败
const purchaseData: iap.PurchaseData = result.purchaseData;

// ✅ 修复：定义本地 interface 描述所需字段，用 as 断言
interface PurchaseData {
  purchaseToken: string;
  purchaseOrderId: string;
  developerPayload?: string;
}
const purchaseData: PurchaseData = result.purchaseData as PurchaseData;
```

修复要点：
- 本地 interface 只需声明实际访问的字段，不需要完整复制 SDK 类型；
- 所有引用该类型的位置（变量声明、函数参数、数组类型）都要替换；
- `as PurchaseData` 断言是必要的，因为 SDK 返回类型不透明。
