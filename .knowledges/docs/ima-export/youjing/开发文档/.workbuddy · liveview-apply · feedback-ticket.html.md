【需求类型】实况窗场景开放建议（非故障报障）

【应用信息】应用名称：有径；包名：com.youjing.app；APP ID：6917619826312400726。一款个人自助旅行行程管理应用（纯本地、无服务端）：用户出行前规划每日站点，出行中按「当前站 → 下一站」逐站推进。

【背景与诉求】希望实况窗开放「旅行行程」场景，或将「进度类型 PROGRESS」的适用范围扩展到「用户主动发起、有明确起止的行程执行任务完成度」。当前 PROGRESS 仅覆盖手动上传/下载/导入导出/备份恢复等任务，旅行行程进度无法合法套用任一已开放场景：CHECK_IN 明确排除景区打卡；NAVIGATION 要求导航中的路线指引（本应用只做行程管理，无转向级导航）；TIMER 限工具类计时。

【场景描述（逐条符合六项准入原则）】

1. 时段性：以「当日行程执行」为一段，用户手动点击开始有明确起点，走完最后一站或手动结束有明确终点，非单点提醒。

2. 时效性：展示正在进行中的当日行程，非已结束回顾或未来计划。

3. 变化性：当前站、下一站、已完成 N/共 M 站随用户到站打卡持续前移。

4. 触发要求：用户在「旅行中」页主动开启，对后续展示有明确预期，不会自动弹出。

5. 价值约束：仅展示行程进度，不含任何营销、广告、优惠券。

6. 时长上限：单次不超过 8 小时，超时或进程结束即移除。

【申请历史】2026-10-26 首次申请实况窗服务（开发调测）被驳回，理由「您申请的场景不在已开放场景内」；2026-11-10 已补充材料重申（审核中）。特此反馈场景开放需求，盼评估将旅行行程纳入实况窗开放范围，谢谢。
