# Build Failure Analyzer

Analyze build errors in C++ and Java with human-readable diagnoses and precise fix recommendations. Focus on C++ template instantiation errors and Java dependency conflicts — common pain points in these languages.

**Note:** This skill provides diagnostic output and fix recommendations. Direct code fixes are optional and should only be applied with user confirmation.

## Workflow

### Step 1: Identify the Error Source

Determine which language the error is from based on the user's pasted output.

- **C++ errors**: Mention `.cpp`/`.hpp`/`.h` files, `g++`/`clang++`, template instantiation errors, linker errors
- **Java errors**: Mention `.java` files, `mvn compile`/`gradle build`, dependency conflicts, classpath issues

Build commands for reference (DO NOT run these — let the user build):
- **C++**: `make`, `cmake --build build`, `g++ -std=c++17 main.cpp`, `clang++ -std=c++17 main.cpp`
- **Java**: `mvn compile`, `mvn clean install`, `gradle build`, `javac Main.java`

**Important Notes:**
- **C++**: C++ template errors are notoriously verbose — focus on the **first template instantiation failure**, not the entire stack trace
- **Java**: Dependency conflicts often appear as `NoSuchMethodError`, `ClassNotFoundException`, or Maven/Gradle resolution warnings

**Why C++ Template Errors Are Verbose (100+ lines):**
Template instantiation is a recursive process. When a template fails, the compiler outputs the full instantiation chain:
1. Each level of template nesting produces a new line in the trace
2. STL algorithms call internal templates, which call more templates
3. The instantiation context (top 10-20 lines) shows where YOUR code triggered the error
4. The remaining 100+ lines are internal STL implementation details — safe to ignore

**What to focus on:**
- The first error line (your code location)
- The instantiation context section (which template + arguments failed)
- Ignore: internal STL traceback, candidate template notes, system header paths

### Step 2: Parse the Error Output

Extract from the compiler output:
- **File paths** and **line numbers**
- **Error type** (type mismatch, missing include, undefined reference, dependency conflict, etc.)
- **The specific symbol or expression** that failed

Read the relevant file(s) at the indicated lines. If the error references a type or function defined elsewhere, find its definition to understand the expected signature.

### Step 3: Provide Fix Recommendations

Provide **targeted fix recommendations only** — do not refactor surrounding code.

**Important:** Present fix recommendations for user review. Do NOT apply fixes automatically unless user explicitly confirms.

**FORMAT REQUIREMENT:** After completing the analysis, you MUST output the diagnosis using the exact format specified in Step 4.

#### Common C++ Errors

| Error Pattern | Typical Fix |
|---|---|
| `no matching function for call to 'X'` | Template instantiation failed — check parameter types. Often a mismatch in template argument deduction. |
| `template instantiation recursion exceeded` | Circular template dependency. Simplify or break the recursion with specialization. |
| `use of undeclared identifier 'X'` | Missing include, namespace issue, or typo. Check if defined in a header file. |
| `invalid operands to binary expression` | Operator not overloaded for these types. Define the operator or cast types. |
| `undefined reference to 'X'` | Linker error — function declared but not defined. Check if implementation file is compiled/linked. |
| `redefinition of 'X'` | Header guard missing or duplicate include. Add `#pragma once` or `#ifndef/#define/#endif`. |
| `expected primary-expression before 'X'` | Syntax error — missing semicolon, brace mismatch, or incorrect template syntax. |
| `cannot convert 'A*' to 'B*'` | Type mismatch — missing cast, wrong inheritance hierarchy, or template mismatch. |

**For C++ template errors:** The compiler output is massive (100+ lines). Focus on the **instantiation context** near the top — it tells you which template and which arguments failed.

**Always include this note in your output:**
> **Note:** C++ template errors are verbose because template instantiation is recursive. Each level of nesting produces a trace line. Focus on the instantiation context (top 10-20 lines) — the remaining internal STL traceback can be ignored.

#### Common Java Errors

| Error Pattern | Typical Fix |
|---|---|
| `java.lang.NoSuchMethodError` | Dependency conflict — multiple versions of the same library on classpath. Use `mvn dependency:tree` to identify. |
| `java.lang.ClassNotFoundException` | Class not found — missing dependency or incorrect package name. Check imports and pom.xml/dependencies. |
| `java.lang.NoClassDefFoundError` | Runtime classpath missing — dependency present at compile-time but not runtime. Check scope (compile vs runtime). |
| `Duplicate class X` | Duplicate class files — multiple jars with same class. Exclude one via Maven/Gradle dependency exclusions. |
| `package X does not exist` | Missing import or wrong package name. Verify imports and package declarations match directory structure. |
| `cannot find symbol` | Symbol not accessible — private/package-private access, wrong import, or missing dependency. |
| `incompatible types: X cannot be converted to Y` | Type mismatch — wrong generic type, missing cast, or API change. |
| `method X in class Y cannot be applied to given types` | Argument mismatch — wrong number or type of arguments. Check method signature changes. |

**For Java dependency conflicts:**
- Run `mvn dependency:tree -Dincludes=groupId:artifactId` to trace where conflicting versions come from
- Use `<exclusion>` in pom.xml or `implementation exclude` in Gradle to remove problematic transitive dependencies
- Consider `<dependencyManagement>` section to enforce consistent versions across the project

### Step 4: Output Format (STRICT REQUIREMENT)

**YOU MUST use the exact diagnostic output structure below. DO NOT deviate from this format.**

**For C++ errors:**
```
[C++ TEMPLATE ERROR DIAGNOSIS]
Error Type: <e.g., Template instantiation failure, type mismatch>
Location: <file>:<line>

[INSTANTIATION CONTEXT]
<Brief description of which template and arguments failed>

[ROOT CAUSE]
<One-sentence explanation of the underlying issue>

[RECOMMENDED FIX]
<Specific code change with line number if applicable>
```

**For Java errors:**
```
[JAVA BUILD ERROR DIAGNOSIS]
Error Type: <e.g., NoSuchMethodError, ClassNotFoundException>
Location: <class>:<line>

[DEPENDENCY CONTEXT]
<Which dependency/classpath issue caused this>

[ROOT CAUSE]
<Brief explanation of the conflict>

[RECOMMENDED FIX]
<Specific pom.xml/Gradle change or version update>
```

**MANDATORY:**
- MUST use the exact section headers shown above
- MUST include all four sections for each error type
- MUST NOT invent new section names or use non-standard headers

- Summarize the recommended fix clearly

- Only apply fixes with explicit user confirmation
- If user confirms, use targeted Edit operations
