有径 · 实况窗业务场景说明
申请能力：实况窗服务（开发调测阶段）　场景类型：进度类型（PROGRESS） 应用名称：有径　应用包名：com.youjing.app　APP ID：6917619826312400726 文档版本：v2.0（2026-11-10，重申）
一、应用与业务说明
「有径」是一款个人自助旅行行程管理应用。用户在出行前把每天的游览站点、餐次与交通方式排成一份行程；出行期间，用户需要频繁确认「现在该去哪一站、下一站是什么、今天整体走到哪了」。这些查看动作多发生在锁屏、步行或换乘途中，反复解锁手机并重新打开应用成本高。
本应用为纯本地应用，行程数据保存在设备本地，不依赖服务端。实况窗用于在用户出行期间，把「当日行程执行」这一正在进行的任务的完成度（当前站、下一站、已完成 N/共 M 站）常驻在锁屏、通知中心与状态栏，用户无需反复进入应用。
二、场景类型说明：行程执行任务的完成度
本场景的核心是「任务完成度」展示：用户出发前手动创建当日任务清单（若干站点），出行期间任务逐项完成，实况窗展示总任务量、已完成量、当前任务项与下一任务项。它与文件导出等任务进度在信息结构上同构：有总量、有完成量、有当前项、有下一项；由用户主动触发；任务完成即结束。
进度数据来源为用户在应用内的到站打卡操作：每完成一站，完成度前移一格（N→N+1），当前站与下一站文本随之更新。不展示百分比之外的任何推断性内容。
三、准入原则符合性
准入约束
本场景的满足方式
时段性
以「当日行程执行」为一个完整任务时段：用户手动点击开始时有明确开始，走完当日最后一站或手动结束时有明确结束，不是单点提醒。
时效性
展示的是正在进行中的当日行程任务，而非已结束的回顾或未来计划的提醒。
变化性
当前站、下一站、已完成站数随用户到站打卡持续刷新，完成度单调前移。
触发要求
由用户在「旅行中」页主动点击「开始当日行程」触发，用户对随后的实况窗展示有明确预期；不会自动弹出。
价值约束
仅展示行程进度（当前站、下一站、第 N 站共 M 站），不出现任何营销、广告、优惠券内容。
时长上限
单次展示上限 8 小时；超过时长的日程不纳入本次实况窗，超时自动结束。
四、场景节点与展示时机
节点一 · 开启：用户在「旅行中」页点击开始当日行程，创建实况窗，胶囊态出现在状态栏。
节点二 · 进行中：实况窗展示当前站点、下一站与当日行程完成度；用户停留在某一站期间不频繁刷新，仅在站点变化时更新。
节点三 · 打卡/切换站点：用户在应用内完成到站打卡或切换到下一站，实况窗内容实时刷新，完成度前移一站。
节点四 · 结束：走完当日最后一站，或用户手动结束行程，实况窗结束并从锁屏、通知中心移除。
五、胶囊态与卡片态设计
胶囊态（状态栏/锁屏顶部）：图标 + 文本（如 Day 2 · 京都），右侧当前完成度（如 2/5）。
卡片态（通知中心/锁屏卡片）：标题为当前站点名称（如 清水寺）；正文为下一站与交通方式（如 下一站 二年坂 · 步行 8 分钟）；进度条为第 N 站 / 共 M 站；辅助文本为剩余站数（如 还剩 3 站）。点击拉起应用并回到「旅行中」页。
以上内容均为行程进度信息，不含营销文案；配色与字号遵循《实况窗设计规范》。详见附件 UX 设计图。
六、数据来源与更新机制
使用 Live View Kit 端侧接口（startLiveView / updateLiveView / stopLiveView）在本地创建与更新，不依赖 Push Kit 云侧创建。行程数据全部来自设备本地存储。
更新时机与应用内状态一致：开启、打卡、切换站点、结束；每次更新序列号严格递增。
七、时长、终止与异常处理
单次实况窗时长不超过 8 小时，达到上限自动结束。
用户手动结束行程时立即停止实况窗。
应用进程结束时实况窗随之结束，不残留过期信息。
权益未开通或接口调用失败时仅记录日志并降级，不影响应用主流程。
八、隐私与合规
实况窗仅展示用户自行创建的行程站点名称与完成度，不涉及个人身份信息、位置轨迹上传或任何第三方数据共享；全部数据保存在设备本地。展示内容不含营销、广告、优惠券。
