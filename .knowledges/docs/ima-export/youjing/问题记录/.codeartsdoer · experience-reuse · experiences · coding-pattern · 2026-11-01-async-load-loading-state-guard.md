# 异步加载页面必须有 loading 态保护防止误导性空态

## Scenario

页面在 `aboutToAppear` 中发起异步数据加载（数据库查询、网络请求等），数据加载完成前页面的 `@State` 变量保持初始值（通常是空数组、0、空字符串）。如果 build() 函数中直接根据这些初始值渲染 UI，用户在加载完成前会看到误导性的空态（"还没有行程"、"还没有勋章"）或默认数据（¥0 费用页面），而非加载指示器。

## Key Signals

- 页面打开后短暂闪现"还没有XX"的空态文案，然后突然变为有数据的状态
- 页面打开后显示 ¥0 或默认值，加载完成后数字跳变
- 列表页打开后空白，加载完成后突然出现内容（无过渡）
- 分段标签（segments）数量在加载前后不一致（默认3项 → 实际5项）

## Essence

问题的根源是：**`@State` 的初始值（空数组、0、空字符串）与"数据为空"的业务语义是不同的，但 UI 渲染逻辑没有区分这两种状态**。

- `loaded = false` + `trips = []`：数据还在加载，不应显示空态
- `loaded = true` + `trips = []`：数据确实为空，应该显示空态

不加 `loaded` 门控时，两种状态在 UI 上表现相同，用户无法区分"正在加载"和"确实没有数据"。

## Approach

1. **每个异步加载的页面添加 `loaded` 状态变量**：初始为 `false`，加载完成后置为 `true`
2. **build() 中三态渲染**：
   - `!loaded`：显示 loading 指示器（spinner、"加载中"文案）
   - `loaded && data.length === 0`：显示空态文案
   - `loaded && data.length > 0`：显示正常内容
3. **动态内容（如 segments）在加载前不渲染或渲染占位**：避免加载前后数量跳变

```typescript
// ❌ 错误：不加门控，初始空数组直接显示空态
if (this.trips.length === 0) {
  Text('还没有行程')
}

// ✅ 正确：三态渲染
if (!this.loaded) {
  LoadingProgress()
} else if (this.trips.length === 0) {
  Text('还没有行程')
} else {
  // 正常列表渲染
}
```

## Faster Next Time

- 在页面模板中预设 loading 状态变量和三态渲染结构，作为编码约定
- 代码审查时检查：每个 `aboutToAppear` 中有异步操作的页面，build() 中是否有对应的 loading 门控
- 特别注意费用/统计类页面：加载期间显示 ¥0 比显示空列表更误导

## Applicability Boundaries

- **适用**：所有在 `aboutToAppear` 中有异步加载的页面
- **不适用**：纯同步数据（如本地常量、已加载的 @StorageProp）的页面
- **注意**：对于从路由参数获取初始数据的页面（如 `@Prop tripId`），如果参数已就绪则不需要 loading 态，但如果参数需要异步解析（如从 activeTripId 查询 tripId）则仍需要

## Evidence or Examples

在 HarmonyProject2 项目中发现的5个缺乏 loading 态保护的页面：

| 页面 | 初始值 | 加载期间显示 | 证据 |
|---|---|---|---|
| TripsPage | `trips = []` | "还没有行程"空态 | TripsPage.ets:71,410 |
| SpotPickPage | `loaded = false`, groups 空 | 空白列表 | SpotPickPage.ets:58,432 |
| StayPickPage | `picks = []` | 空白列表 | StayPickPage.ets:56 |
| MapPage | `loaded = false`, stops 空 | 空白地图 | MapPage.ets:63 |
| ExpensePage | `budgetTotal = 0` | ¥0 费用页面 | ExpensePage.ets:131,154 |
| MinePage | `badgeCount = 0` | "还没有勋章" | MinePage.ets:59,158 |
| ItineraryPage | `segments = [Day1,Day2,Day3]` | 3个分段标签（可能与实际天数不符） | ItineraryPage.ets:83-85 |
