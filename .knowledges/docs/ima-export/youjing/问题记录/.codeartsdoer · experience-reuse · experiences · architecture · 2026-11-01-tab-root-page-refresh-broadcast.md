# 多 Tab 根页通过显示广播实现切回时数据刷新

## Scenario

在多 Tab 应用中，用户从一个 Tab 切到另一个 Tab 再切回来时，期望看到最新数据（如新增的行程、变更的费用）。但 Tab 根页的 `aboutToAppear` 只在首次创建时调用一次，后续切回不会重新触发。如果根页只依赖 `aboutToAppear` 取数，切回时数据会停留在首次加载的旧值。

更隐蔽的是：某些 Tab 根页的 `onShown` 回调在真机上不 reliably 触发（取决于 Tab 实现方式），导致依赖 `onShown` 刷新的根页永不更新。

## Key Signals

- 在 Tab A 新增数据后，切到 Tab B 再切回 Tab A，看不到新增的数据
- 根页的 `aboutToAppear` 只在冷启时调用一次，后续切 Tab 不触发
- `onShown` 回调在真机上不 reliably 触发（模拟器可能正常）
- 用户需要手动下拉刷新才能看到最新数据

## Essence

问题的核心是：**Tab 切换不重建 TabContent，所以 `aboutToAppear` 不会重新调用；而 `onShown` 在某些 Tab 实现下不 reliably 触发**。需要一个可靠的、跨 Tab 的通知机制来驱动根页刷新。

解决方案是**显示广播模式**：

1. Tab 容器的 `onChange` 和 `onTabBarClick` 回调中，广播"当前显示的 Tab 序号"
2. 每个 Tab 根页通过 `@StorageProp(TAB_SHOWN_KEY) @Watch` 监听广播
3. 当广播的 Tab 序号与自己的 Tab 序号匹配时，触发数据刷新

这个模式的关键优势：
- `@StorageProp + @Watch` 是 ArkTS 框架保证的响应式机制，比 `onShown` 更可靠
- 广播通过 AppStorage 传递，不受 Tab 实现细节影响
- 同时支持 `onChange`（切到新 Tab）和 `onTabBarClick`（再点当前 Tab 回到根页）两种场景

## Approach

### 1. 定义广播常量和工具函数

```typescript
// AppNav.ets
export const TAB_SHOWN_KEY: string = 'tab_shown_tick';
export const TAB_SWITCH_KEY: string = 'tab_switch_request';

// 广播函数：通知所有 Tab 根页"当前显示的是哪个 Tab"
export function announceTabShown(tabIndex: number): void {
  AppStorage.setOrCreate(TAB_SHOWN_KEY, tabIndex);
}
```

### 2. Tab 容器在切换时广播

```typescript
// Index.ets
HdsTabs({ controller: this.hdsController, index: this.initialTabIndex }) {
  // ... TabContent ...
}
.onChange((index: number) => {
  announceTabShown(index);
})
.onTabBarClick((index: number) => {
  // 再点当前 Tab = 清空栈回到根页
  stackOfTab(index).clear();
  announceTabShown(index);
})
```

### 3. 每个 Tab 根页监听广播并刷新

```typescript
// MapPage.ets / TripsPage.ets / ExpensePage.ets / MinePage.ets
@StorageProp(TAB_SHOWN_KEY) @Watch('onDockShown') shownTick: number = -1;

private onDockShown(): void {
  if (this.shownTick === TAB_MAP) {  // 自己的 Tab 序号
    this.reload();
  }
}
```

### 4. 不读数据的 Tab 根页可以不监听

如果某个 Tab 根页不展示动态数据（如纯门面页），可以安全地不监听广播。

## Faster Next Time

- 在新建 Tab 根页时，直接复制监听模式（`@StorageProp + @Watch + onDockShown`）
- 在 AppNav.ets 中维护 Tab 序号常量与根页的对应关系表
- 代码审查时检查：每个 Tab 根页是否监听了 TAB_SHOWN_KEY（除非确认不需要刷新）

## Applicability Boundaries

- **适用**：使用 HdsTabs/Tabs 组件的多 Tab 应用、Tab 根页需要展示动态数据
- **不适用**：单页面应用、Tab 根页只展示静态内容
- **注意**：
  - Tab 序号常量（TAB_MAP=0, TAB_ITINERARY=1 等）必须与 TabContent 顺序、DOCK_TABS 数组下标三者同步
  - 冷启深链时不用 changeIndex（真机实测不生效），而是把目标 Tab 作为 HdsTabs 构造参数的初始 index
  - `onTabBarClick` 清空栈后，根页的 @State 变量会重置为初始值，需要重新加载

## Evidence or Examples

在 HarmonyProject2 项目中的实现：

- 5个 Tab：Map(0) / Trips(1) / Plan(2) / Expense(3) / Mine(4)
- 4个 Tab 根页监听 TAB_SHOWN_KEY：MapPage、TripsPage、ExpensePage、MinePage
- 1个 Tab 根页不监听：YoujingStartPage（Plan tab，纯门面页不读行程数据）
- 广播入口：Index.ets:237-244（onChange）和 Index.ets:248-259（onTabBarClick）
- 常量定义：AppNav.ets:26-33（TAB_MAP=0 到 TAB_MINE=4）
- 真机实测坑：`onShown` 在 HdsTabs 下不 reliably 触发，`@StorageProp + @Watch` 是可靠替代
