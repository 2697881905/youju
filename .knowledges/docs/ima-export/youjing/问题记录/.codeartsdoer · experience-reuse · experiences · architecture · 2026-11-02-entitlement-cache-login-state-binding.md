# 权益缓存必须与登录态生命周期绑定——登出清除、登录刷新、判定时检查

## Scenario

商业化应用中，权益数据（订阅状态、通行证、免费额度）通常由 BFF 返回后缓存在端侧 preferences 中，TTL 过期前用缓存判定付费墙。登录态管理由独立的 AccountStore 负责。当两者生命周期没有显式绑定时，会出现三类严重问题：

1. **登出后缓存残留**：用户登出回到游客模式，但权益缓存仍保留登录用户的订阅/通行证数据，游客可以导出/使用付费功能。
2. **登录后缓存不刷新**：游客登录为付费账号后，权益缓存仍是游客的空权益，付费用户被当作免费用户拦截。
3. **判定时不检查登录态**：`canExport()` 等判定方法只看缓存内容，不区分当前是登录还是游客，导致付费墙在错误的状态下做出错误判断。

## Key Signals

- 登出后游客模式下 `canExport()` 仍返回 true（缓存残留）
- 登录后付费用户 `canExport()` 返回 false（缓存未刷新）
- `EntitlementStore.clear()` 方法已定义但全工程无调用方
- `AccountStore.logout()` 只清除登录态，不通知 EntitlementStore
- `AccountStore.login()` 成功后不触发权益刷新或设备重新激活
- `EntitlementStore.init()` 从 preferences 恢复缓存时不区分登录态

## Essence

权益缓存与登录态是两个独立的生命周期，但商业正确性要求它们必须同步。核心矛盾是：缓存为了离线可用而存在，但缓存不感知登录态变化，导致缓存内容与当前用户身份不匹配。

解决方案不是取消缓存，而是建立三条绑定规则：
1. **登出必清除**：logout 时必须调用 `EntitlementStore.clear()`，清空内存缓存和 preferences 持久化
2. **登录必刷新**：login 成功后必须触发 `DeviceActivator.reactivate()` 或 `EntitlementStore.refresh()`，拉取新用户权益
3. **判定时校验**：`canExport()` 等判定方法应检查当前登录态，游客态下即使缓存有数据也应保守拒绝

## Approach

1. 在 `AccountStore.logout()` 中追加 `await EntitlementStore.clear()`，确保登出后内存和持久化都被清除
2. 在 `AccountStore.login()` 成功分支中追加 `await DeviceActivator.reactivate(context)`，确保登录后立即拉取新用户权益
3. 在 `EntitlementStore.canExport()` 入口处增加登录态检查：`if (AccountStore.isGuest()) return false`（保守策略：游客默认拒绝导出）
4. 在 `EntitlementStore.init()` 恢复缓存时，检查缓存对应的用户与当前登录用户是否一致，不一致则丢弃缓存

## Faster Next Time

- **审计检查清单**：任何有登录态 + 权益缓存的商业化应用，必须检查以下三个接线点：
  - `logout()` → `EntitlementStore.clear()` 是否接线
  - `login()` 成功 → `EntitlementStore.refresh()` 或 `reactivate()` 是否接线
  - `canExport()` / `canGenerate()` 等判定方法是否检查登录态
- **grep 验证**：搜索 `EntitlementStore.clear` 的调用方，如果只有定义没有调用，就是接线缺口
- **设计审查信号**：如果 `clear()` 方法已定义但从未被调用，几乎必然存在登出不清除缓存的 bug

## Applicability Boundaries

- 适用于：任何有登录态切换 + 权益/配置缓存的商业化应用
- 不适用于：无登录态的纯本地应用，或权益完全由服务端实时判定不缓存的应用
- 保守策略（游客默认拒绝）适用于导出/付费功能；对于免费功能不应误拒

## Evidence or Examples

HarmonyProject2 项目中发现的三个严重问题：

1. **登出不清除**（严重）：`AccountStore.logout()`（AccountStore.ets:125-140）只清除登录态，不调用 `EntitlementStore.clear()`（EntitlementStore.ets:116-130 已定义但从未被调用）。MinePage.ets:95 登出只调 `AccountStore.logout()`。

2. **登录不刷新**（严重）：`AccountStore.login()`（AccountStore.ets:96-119）成功后不调用 `EntitlementStore.update()` 或 `DeviceActivator.reactivate()`。YoujingStartPage.ets:86-88 登录后只调 `TripDao.adoptGuestData`，LoginView.ets:74-82 登录后只调 `onSignedIn`。

3. **判定不检查登录态**（严重）：`EntitlementStore.canExport()`（EntitlementStore.ets:85-87）只看缓存内容，不检查 `AccountStore.isGuest()`。`EntitlementStore.init()`（EntitlementStore.ets:49-65）从 preferences 恢复缓存时不区分登录态。
