# replacePath 替换栈顶后返回路径与业务期望不一致

## Scenario

在向导式流程中，某个页面（如"生成中"页面）完成后使用 `replacePath` 跳转到结果页面（如"行程详情"页面），意图是"生成中页面不需要保留在栈中，用户不应该返回到生成中页面"。但 `replacePath` 的语义是**替换当前栈顶页面**，这意味着结果页面的上一页变成了生成中页面的前一页（如住宿选择页），而非业务期望的页面（如行程列表页）。

用户在结果页面按返回键时，会回到向导流程的中间页面（住宿选择页），而不是回到流程的起点或列表页，造成导航困惑。

## Key Signals

- 用户在结果页面按返回键，落到了向导流程的中间步骤页面
- 使用 replacePath 后，栈的深度减少了1（原页面被替换而非新增）
- popToName 的目标页面可能不在栈中（如果它已经被 replacePath 替换掉了）

## Essence

`replacePath` 的栈语义与 `pushPath` 不同：

| 操作 | 栈变化 | 新页面返回目标 |
|---|---|---|
| `pushPath(B)` from A | [..., A, B] | A（前一页） |
| `replacePath(B)` from A | [..., B]（A被移除） | A的前一页 |

业务意图通常是"完成后不可回退到生成中页面"，但 replacePath 同时改变了返回路径——结果页面的返回目标变成了生成中页面的前一页，而非业务期望的行程列表。

可选方案对比：

1. **replacePath**：生成中页面被替换，返回落到向导中间页 — 返回路径不符合期望
2. **pushPath + popToName**：生成中页面保留在栈中，但可以在结果页面通过 popToName 跳过 — 栈管理复杂
3. **pushPath + clear + pushPath**：先 push 结果页面，然后清栈重建 — 操作繁琐但返回路径可控
4. **replacePath + 显式返回导航**：使用 replacePath 但在结果页面自定义返回按钮，用 popToName 导航到期望的页面 — 最简单且可控

## Approach

推荐方案4：**使用 replacePath 进入结果页面，但在结果页面提供自定义返回导航**：

1. 使用 `replacePath` 进入结果页面（生成中页面不需要保留）
2. 在结果页面不依赖系统返回按钮的默认行为，而是提供自定义返回逻辑
3. 自定义返回使用 `popToName` 导航到业务期望的页面（如行程列表）
4. 如果 popToName 失败（目标不在栈中），则 pushPath 兜底

```typescript
// 生成中页面：用 replacePath 进入结果页面
APP_NAV.replacePath({ name: 'Itinerary', param: trip.id });

// 结果页面：自定义返回逻辑
private goBack(): void {
  if (this.pathStack.popToName('YoujingStart') < 0) {
    this.pathStack.pushPath({ name: 'YoujingStart' });
  }
}
```

## Faster Next Time

- 在使用 replacePath 前，先画出栈的变化图，确认返回路径是否符合业务期望
- 如果返回路径不符合期望，在目标页面添加自定义返回导航
- 在代码审查中检查：每个 replacePath 的调用方，目标页面的返回路径是否正确

## Applicability Boundaries

- **适用**：使用 NavPathStack 管理导航栈的应用、有"不可回退"步骤的向导流程
- **不适用**：简单的 push/pop 导航场景、不需要控制返回路径的应用
- **注意**：如果目标页面同时需要支持"从列表进入"和"从生成进入"两种路径，返回逻辑需要根据来源区分

## Evidence or Examples

在 HarmonyProject2 项目中的具体案例：

- GeneratingPage 使用 `replacePath({ name: 'Itinerary' })` 进入 ItineraryPage
- 栈变化：[..., StayPick, Generating] → [..., StayPick, Itinerary]
- ItineraryPage 的系统返回按钮会回到 StayPickPage（住宿选择页），而非用户期望的行程列表
- 证据：GeneratingPage.ets:111 `APP_NAV.replacePath({ name: 'Itinerary', param: trip.id })`
- 同族问题：GenerateFailedPage 也使用 replacePath，失败页面的返回路径同样受影响
