# HarmonyOS IAP Kit 三步购买链路——createPurchase → 服务端校验 → finishPurchase

## Scenario
HarmonyOS 应用需要接入应用内支付（IAP）销售虚拟商品或订阅服务。`@kit.IAPKit` 的购买流程不是简单的"调起支付→完成"两步，而是涉及三个必须按序完成的环节，漏掉任何一步都会导致交易异常或掉单。

## Key Signals
- `iap.createPurchase()` 成功返回 `purchaseData` 后，交易并未关闭——如果不调用 `iap.finishPurchase()`，该商品会被标记为"已购买但未交付"，用户无法再次购买同类商品。
- 客户端支付成功但网络上报失败（掉单）时，`iap.queryPurchases()` 可以查回未交付的购买记录，但必须在应用启动时主动调用，否则用户已付款却拿不到权益。
- 用户在收银台点取消会返回错误码 `1001860000`，这不是真正的错误，不应进入错误处理流程。
- `ProductType` 选错会导致购买行为与业务预期不符：`CONSUMABLE`（消耗型，需手动消耗）、`NONCONSUMABLE`（非消耗型，一次购买永久有效）、`AUTORENEWABLE`（自动续期订阅）。

## Essence
IAP Kit 的购买链路是三步而非两步：① `createPurchase` 调起收银台完成支付 → ② 将 `purchaseToken` 发到自己的服务端校验并写入权益 → ③ `finishPurchase` 关闭交易确认发货。三步必须按序完成，缺任何一步都会留下未关闭的交易或掉单。恢复购买（restore）的本质是用 `queryPurchases` 查回所有未交付的记录，然后对每条重复步骤②③。

## Approach
1. **环境检查**：购买前先调 `iap.queryEnvironmentStatus()`，确认当前地区支持 IAP，避免后续流程异常。
2. **发起购买**：
   ```typescript
   import { iap } from '@kit.IAPKit';
   const parameter: iap.CreatePurchaseParameter = {
     productType: iap.ProductType.NONCONSUMABLE, // 通行证=非消耗型
     productId: 'trip_pass_001',
     developerPayload: 'optional-context'
   };
   const result: iap.CreatePurchaseResult =
     await iap.createPurchase(context, parameter);
   ```
   - 产品类型映射：通行证/永久权益 → `NONCONSUMABLE`；月/年订阅 → `AUTORENEWABLE`；次数包 → `CONSUMABLE`。
3. **服务端校验**：将 `result.purchaseData.purchaseToken` 发到 BFF `/v1/iap/verify`，服务端校验有效性后写入 order/subscription/trip_pass 表，返回最新权益快照。
4. **发货确认**：
   ```typescript
   await iap.finishPurchase(context, {
     productId: result.purchaseData.productId,
     purchaseToken: result.purchaseData.purchaseToken
   });
   ```
   - `finishPurchase` 是 `consumePurchase`（已废弃）的替代，适用于所有商品类型。
5. **恢复购买**（应用启动时调用）：
   ```typescript
   const purchases: iap.PurchaseInfo[] =
     await iap.queryPurchases(context, {
       queryType: iap.PurchaseQueryType.UNFINISHED
     });
   for (const p of purchases) {
     await verifyWithBff(p.purchaseToken);
     await iap.finishPurchase(context, {
       productId: p.productId,
       purchaseToken: p.purchaseToken
     });
   }
   ```
   - `queryType` 选 `UNFINISHED` 只查未交付的记录，避免遍历全部历史。
6. **用户取消处理**：`createPurchase` 的 catch 中，如果 `err.code === 1001860000`，静默返回不报错——这是用户主动取消，不是系统错误。

## Faster Next Time
- 接入 IAP 时，先画三步链路图（createPurchase → verify → finishPurchase），确认每一步都有对应的代码路径和错误处理。
- `finishPurchase` 是最容易遗漏的一步——在代码 review 时专门检查每个 `createPurchase` 成功路径是否最终都调了 `finishPurchase`。
- 恢复购买不是可选功能，是必须功能——掉单（支付成功但上报失败）在生产环境中一定会发生，没有恢复购买就是丢钱。
- `ProductType` 在 AGC 配置商品时就要确定，代码里的 `productType` 必须与 AGC 配置一致，否则 `createPurchase` 会报错。
- `queryEnvironmentStatus` 在 debug 包里可以跳过（模拟器可能不支持），但发布包必须调用。

## Applicability Boundaries
- 适用：HarmonyOS Stage 模型应用，API 4.0.0(10)+，需要销售虚拟商品或订阅服务。
- `AUTORENEWABLE` 不支持 Wearable 设备；`NONRENEWABLE` 从 API 5.0.2(14) 起支持。
- 元服务（原子化服务）从 API 5.0.0(12) 起支持 IAP。
- 华为应用市场分发的虚拟服务通常必须走华为 IAP，不能自己接第三方支付——具体条款以上架时最新协议为准。
- `developerPayload` 的内容在服务端校验时可以用来传递上下文（如 localTripId），但不要放敏感信息——它可能被篡改。

## Evidence or Examples
- 项目中通行证（9.9 元/行程）使用 `NONCONSUMABLE`，月订阅（19.9 元）和年订阅（98 元）使用 `AUTORENEWABLE`。
- `IapStore.ets` 实现了 `purchasePass()` / `purchaseSubscription()` / `restorePurchases()` / `verifyWithBff()` / `finishPurchase()` 五个方法。
- `PricingPage.ets` 的购买按钮接 `IapStore.purchasePass()`，恢复购买按钮接 `IapStore.restorePurchases()`。
- BFF 侧 `/v1/iap/verify` 接口校验 `purchaseToken` 后写入 order 表 + subscription 或 trip_pass 表，返回最新权益快照。
- 官方文档：`https://developer.huawei.com/consumer/cn/doc/harmonyos-references/iap-iap`
