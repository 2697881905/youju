# 多页面应用主链路完整性普查方法论

## Scenario

当一个多页面应用（尤其是有向导式流程的应用）发展到一定规模后，主链路上的页面数量增加、入口分散、数据流复杂化，容易出现"局部正确但链路断裂"的问题——单个页面功能正常，但页面之间的导航、数据传递、生命周期协调存在隐蔽缺陷。这类问题在常规功能测试中不易暴露，因为测试通常聚焦单个页面而非完整链路。

触发条件：应用有3个以上页面的向导式主流程，且有多个入口可以进入该流程。

## Key Signals

以下信号提示需要做一次主链路完整性普查：

1. 用户反馈"从某个入口进去后数据不对"——多入口未统一初始化
2. 页面加载时短暂闪现空态或默认数据——异步加载缺少 loading 保护
3. 返回操作落到意外页面——replacePath/popToName 栈语义与业务期望不一致
4. 切换 Tab 后数据不刷新——根页未监听 Tab 显示广播
5. 路由参数类型不匹配导致页面白屏或异常——pushPath 参数与路由注册消费函数不匹配

## Essence

主链路完整性普查的核心是：**沿着用户实际走的路径逐页检查，而非按文件目录逐个审查**。关键在于把检查维度固定为5类，每类都有明确的验证方法和证据要求：

1. **页面入口可达性**：路由注册 + 导航参数类型匹配
2. **页面间数据传递**：参数从输入到消费的完整链条无断裂
3. **页面生命周期**：异步加载有 loading 态保护、数据未就绪有兜底渲染
4. **导航回退**：返回路径与业务期望一致、popToName 目标在栈中
5. **Tab 切换**：根页监听显示广播、切回时数据刷新

## Approach

### 准备阶段

1. 画出主链路的完整页面序列（从入口到终态），标注每个页面的路由名
2. 识别所有可以进入主流程的入口（首页 CTA、Tab 根页按钮、空态按钮等）
3. 列出跨页面共享的数据载体（单例、全局状态、路由参数）

### 逐维度检查

**维度1：页面入口可达性**
- 检查每个页面在路由表中是否注册
- 检查每个 pushPath/replacePath 的 name 是否与路由注册名一致
- 检查 param 类型是否与路由消费函数的提取逻辑匹配（typeof null === 'object' 陷阱）

**维度2：页面间数据传递**
- 追踪共享数据载体从第一个写入页面到最后一个消费页面的完整路径
- 检查每个入口是否在进入流程前调用了重置/清空操作
- 检查"跳步"场景（如一句话直接生成）中未经过的页面数据是否有默认值兜底

**维度3：页面生命周期**
- 检查每个 aboutToAppear 中的异步加载是否有 loading 状态变量
- 检查数据未就绪时 UI 是否会显示误导性空态（"还没有XX"）或默认值（¥0）
- 检查加载完成后 segments/列表等动态内容是否会跳变

**维度4：导航回退**
- 检查 replacePath 进入的页面，返回时会落到哪一页（不是被替换的页面）
- 检查 popToName 的目标页面是否一定在栈中，失败后的兜底是否合理
- 检查自定义返回按钮与系统返回按钮的去向是否一致

**维度5：Tab 切换**
- 检查每个 Tab 根页是否监听了 Tab 显示广播（如 TAB_SHOWN_KEY）
- 检查 onTabBarClick 清空栈后根页是否能正确重新加载
- 检查不读数据的 Tab 根页是否可以安全地不监听广播

### 证据要求

每个发现的问题必须给出 `file:line` 证据，并标注严重程度：
- **阻断**：用户无法完成主流程
- **严重**：用户会遇到可见的错误行为或误导性信息
- **一般**：边界场景或架构反模式，不影响正常使用

## Faster Next Time

- 把5个维度做成检查清单（checklist），每次新增页面或入口时逐项过一遍
- 在路由注册文件中添加注释标注每个路由的参数类型期望
- 在共享数据单例的重置方法旁注释所有需要调用它的入口列表
- 对 aboutToAppear 异步加载的页面，统一引入 loading 状态变量命名约定

## Applicability Boundaries

- **适用**：3个以上页面的向导式流程、多入口应用、多 Tab 应用
- **不适用**：单页面应用、无导航栈的简单应用、纯展示型页面
- **注意**：本方法论关注的是"链路完整性"而非"页面内部正确性"，页面内部的功能测试不在普查范围内

## Evidence or Examples

在 HarmonyProject2（有径/YouJing）项目中执行的一次完整普查：

- 主链路9个页面：Index → LoginView → YoujingStartPage → TripInputPage → PreferenceQAPage → SpotPickPage → StayPickPage → GeneratingPage → ItineraryPage
- 5个入口可进入规划流程：YoujingStartPage、TripsPage（3处）、MinePage、MapPage、ExpensePage
- 普查发现17个问题：0阻断、3严重、14一般
- 3个严重问题：
  - 3个入口缺少 `PlanDraft.fresh()` 调用，旧草稿污染新规划（MinePage.ets:322、MapPage.ets:392、ExpensePage.ets:900）
  - TripsPage 加载期间显示"还没有行程"空态（TripsPage.ets:410）
  - StayPickPage "就住这里"按钮不检查 selectedId 为空（StayPickPage.ets:528-531）
