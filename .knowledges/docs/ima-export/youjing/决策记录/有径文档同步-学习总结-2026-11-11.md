## 本次提炼（增量学习，来源见状态文件 learning_ref）
### 项目事实
1. 「有径」(YouJing) 是 HarmonyOS NEXT 原生 App（包名 `com.youjing.app`，API 26 / targetSdk 26），对标「有据」(`com.youju.app`)；前端纯 ArkTS/ArkUI，**运行时依赖为零**，功能一律用系统 `@kit` API 实现。
2. 工程采用严格分层 `pages → components → model/data/ai/utils → common/design`，**禁止跨层直连**（页面不得直连 RDB 或直发 LLM）；`design/` 与 `common/` 为底层单一事实源（配置/常量/错误码/token 只在此定义）。
3. 商业化改造后存在系统性「接线缺口」风险——方法已定义但全工程无调用方（如 `canGenerate`），普查发现 12 个缺口（3 阻断 / 4 严重 / 4 一般）；BFF 此前从未真起进程、付费路径零测试覆盖。

### 关键决策
1. API 等级以工程实际配置 **API 26 / targetSdk 26** 为准（开发文档 §2.3 未声明），`compatibleSdk=26` 即不向低版本兼容，最低兼容范围列入待办。
2. 免费档默认形态必须保留「本机规则引擎零 token 成本」出口——P0 死锁根因是 BFF 未配置时 `canGenerate()` 恒 false 导致 100% 跳付费页，本地合成不得依赖 BFF。

### 可复用检查项
- **「定义但不调用」接线缺口普查**：对任何新增/改造模块，用 grep 搜方法名/错误码/字段名确认调用方命中 ≥2（定义处 + 至少一处调用），否则标记缺口；优先查阻断级（BFF 契约对齐、错误恢复通道）。可复用于任何「写了但没连上」的改动。
