# 一镜到底飞行修复：截图方角暴露 + 落点偏移后瞬移

## 摘要（Summary）

首页卡片 → 帖子详情的一镜到底飞行有两处缺陷（用户描述：圆角矩形 → 直角矩形 → 瞬移回正确位置并变回圆角）：

1. **飞行中圆角丢失**：作为飞行载体的「卡片截图」（`PostDetailDestination` 里的 `Image`）自身没有圆角，飞行时可见的圆角全部来自**外层裁切窗口**（`radius` 16→24→0，官方值）。窗口放大后其圆角边缘与截图边缘错开，截图的直角边暴露 → 观感「圆角变直角」；交接真图时真媒体自带圆角（`RadiusTokens.lg`=20 / 视频 12）→ 观感「变回圆角」。
2. **落点错位 + 瞬移**：截图用 `.width('100%')`（整页宽 360vp）渲染，而截图是**卡片原尺寸的拷贝**（信息流双列卡 ≈162vp、卡堆 4:3 媒体块 ≈328vp），按页宽渲染相当于整体放大 ~1.1 倍 → 终点时封面区域右/下溢出（约 +32vp / +43vp），真媒体出现时"啪"地对齐 → 观感「落点不对 → 瞬移」。
3. **每日一帖分支额外错位**：卡堆卡面是 4:3（`DECK_MEDIA_RATIO`），但传参用了 `LayoutTokens.cardMediaAspectRatio`（0.75 = 3:4）→ 飞行目标框的比例与卡面不符；声明了「一镜到底飞行目标同比例」的 `DAILY_DECK_MEDIA_RATIO = 4/3` 常量目前**未被使用**。

修复思路：截图按**实测对应节点（媒体位）宽度**渲染（起终两端都像素级对齐），截图自带圆角并随转场从**卡片圆角**过渡到**媒体圆角**；每日一帖恢复 4:3 飞行比例。

## 现状分析（Current State Analysis）

### 飞行链路

- 源页 `HomeTab.openDetailViaNav`：截整卡（`getComponentSnapshot().get(cardId)`）+ 量卡片帧（`cardRectOf`）→ 随 `LongTakeParams` push。
  - 信息流卡：`cardId = 'feedCard-{id}'`（**双列瀑布流**，卡宽 ≈ (360 - 边距)/2 ≈ 162vp，`compact: true`，卡容器圆角 `RadiusTokens.xs` = 6）。
  - 卡堆卡：`cardId = 'deckCardMedia-{id}'`（**仅 4:3 媒体块**，≈328×246，卡容器圆角 `RadiusTokens.md` = 14；媒体块由卡容器 clip 出圆角）。
  - 参考：`PostCard.ets` L241-277、`PostCardMedia.ets` L21-33、`DailyPostDeck.ets` L216-264 / L335-336。
- 目的地 `PostDetailDestination.build`：`NavDestination > Stack(scale/translate/clipHeight/radius 16→24→0) > Stack(position) > [PostDetailView, 截图 Image]`。
  - 官方公式：`initScale = cardW / nodeW` 让「对应节点」（详情媒体位）映射到卡片帧；`clipHeight = cardH / initScale`。
  - 截图当前：`.width('100%')` + `objectFit(Auto)` + `.position(节点局部坐标)` + 无圆角 + 顶层不拦触摸。
- 时序：`postPageOpacity` 50→150ms 升到 1（截图在顶层顶住整帧）；真媒体首帧就绪（`onHeroReady`）后截图 180ms 淡出、真媒体 180ms 淡入（≥300ms、≤1500ms 窗口）。

### 关键数值（以 360vp 宽设备为例）

| 项 | 值 |
| --- | --- |
| 页面宽 / 详情媒体位宽（= 节点实测宽 nodeW） | 360 / 328 |
| 截图当前渲染宽（100%） | 360（= 328 × 1.098） |
| 终点时的溢出 | 右 +32vp、下 +43vp（信息流 3:4 封面区） |
| 信息流卡片圆角 / 卡堆卡片圆角 | `xs` = 6 / `md` = 14 |
| 详情媒体圆角 | `RadiusTokens.lg` = 20（视频播放器 = 12） |

### 根因结论

- 截图渲染宽应为 **nodeW（328）**：`Ws·initScale = cardW`（起点 1:1），`Ws = nodeW`（终点 = 媒体位宽），两端同时成立。
- 截图必须**自带圆角**：componentSnapshot 未保留卡片 clip 的圆角（飞行中方角暴露可证），只靠外层窗口圆角无法在窗口放大后继续生效。
- 卡堆分支的 aspect 需恢复 4/3，否则媒体位框（3:4）与卡面（4:3）不一致。

## 变更（Proposed Changes）

### 1. `entry/src/main/ets/utils/longTake/longTakeAnimationProperties.ets`

**Why**：新增两个随转场驱动的量：截图展示宽度、截图圆角；并让截图宽度在量测阶段确定。

- `LongTakeParams` 增加字段：
  ```ts
  // 源卡片圆角（vp）：截图进场从这里过渡到媒体圆角；0 = 未提供 → 回退 RADIUS_CARD
  cardRadius: number = 0;
  ```
- `LongTakeAnimationProperties` 增加公共字段：
  ```ts
  // 截图展示宽度（vp）= 对应节点实测宽：截图是卡片原尺寸拷贝，按节点宽渲染
  // 才能「起点 1:1、终点与媒体位像素对齐」（用页宽会整体 ~1.1 倍 → 落点溢出后瞬移）
  snapShotWidth: number = 0;
  // 截图自身圆角（vp）：进场从源卡片圆角过渡到媒体圆角（可见圆角不能只靠外层裁切窗口）
  snapShotRadius: number = RADIUS_CARD;
  ```
  私有字段：`cardRadiusValue` / `mediaRadiusValue`（初值 `RADIUS_CARD`，`init` 时记录）。
- `init(...)` 追加两个入参并赋值（`> 0` 才采用，否则回退 `RADIUS_CARD`）：
  `init(cardItemInfo_vp, destNodeId, destNodeFallbackId, rootNodeId, clickedCardId, cardRadius, mediaRadius)`。
- `initParams`：几何校验通过后（`geometryValid = true` 之后）写 `this.snapShotWidth = ui.px2vp(nodeWidth_px);`。
- `doEnterAnimation`：初值段加 `this.snapShotRadius = this.cardRadiusValue;`；350ms 展开的 `animateTo` 块内加 `this.snapShotRadius = this.mediaRadiusValue;`。
- `doBackAnimation`：展开回卡片帧的 `animateTo` 块内加 `this.snapShotRadius = this.cardRadiusValue;`。
- `setFinalStatus`：加 `this.snapShotRadius = this.mediaRadiusValue;`（终态且截图不可见，仅保持字段一致）。

### 2. `entry/src/main/ets/pages/PostDetailDestination.ets`

**Why**：把截图渲染尺寸/圆角接到新字段；计算视频/图片两种媒体圆角。

- import `RadiusTokens`；文件级常量：
  ```ts
  // 视频媒体圆角（与 PostDetailView.videoFace 的 borderRadius(12) 对齐）
  const VIDEO_MEDIA_RADIUS: number = 12;
  ```
- 组件内私有字段 `private mediaRadius: number = RadiusTokens.lg;`，在 `onReady` 读到 `intent` 后：
  `this.mediaRadius = (intent !== null && intent.isVideo) ? VIDEO_MEDIA_RADIUS : RadiusTokens.lg;`
- `tryRegisterCustomTransition` 的 `init(...)` 调用透传 `this.takeParams.cardRadius` 与 `this.mediaRadius`。
- 截图 `Image`：
  - `.width('100%')` → `.width(this.longTakeAnimationProperties.snapShotWidth)`
  - 增加 `.borderRadius(this.longTakeAnimationProperties.snapShotRadius)` + `.clip(true)`
  - 更新注释：说明「按节点宽渲染 = 两端像素对齐」「截图自带圆角 = 飞行中不露直角」「圆角随转场从卡片圆角过渡到媒体圆角」。

### 3. `entry/src/main/ets/components/HomeTab.ets`

**Why**：源页提供卡片圆角；每日一帖恢复 4:3 飞行比例。

- `openDetailViaNav(post, aspect, cover, cardId)` → 追加 `cardRadius: number` 参数；函数体内 `take.cardRadius = cardRadius;`（并更新函数头注释）。
- 卡堆调用（`dailyDeck` 的 `onOpen`）：
  `this.openDetailViaNav(post, DAILY_DECK_MEDIA_RATIO, this.dailyDeckCover(post), 'deckCardMedia-' + post.id, RadiusTokens.md);`
  （比例从 `LayoutTokens.cardMediaAspectRatio`(0.75) 改为 `DAILY_DECK_MEDIA_RATIO`(4/3)；该常量已有「一镜到底飞行目标同比例」注释）
- 信息流调用（`feedPost` 的 `onOpen`）：
  `this.openDetailViaNav(post, LayoutTokens.cardMediaAspectRatio, this.feedCardCover(post), 'feedCard-' + post.id, RadiusTokens.xs);`
- import：`RadiusTokens` 已存在（L27），无需新增。

## 假设与决策（Assumptions & Decisions）

1. **可见圆角改由截图自身承载**：保留外层裁切窗口的 `RADIUS_CARD(16)→RADIUS_EXPANDED(24)→0`（它只塑形窗口自身，尺寸比截图大一圈，互不冲突，最小改动）。
2. **圆角做成过渡（卡片圆角 → 媒体圆角）而非常量**：两端都不产生圆角跳变（起点不跳、交接不跳），代码量约 10 行。
3. **每日一帖飞行比例恢复 4:3**：这是代码自身声明的意图（`DAILY_DECK_MEDIA_RATIO` 注释），顺带把该帖在详情里的媒体框对齐到卡面比例（3:4→4:3），`preserveContent` 随之从 false→true（Contain，符合 `DetailMediaCarousel` 注释「详情阅读时保留原图完整内容」）。
4. **其他 `PostDetail` 入口不受影响**：圈子详情 / 用户主页 / 私信三处 push 未传 `LongTakeParams`，不走自定义转场（已 grep 确认仅 HomeTab 构造 `LongTakeParams`）。
5. **截图高度继续交给 `objectFit(Auto)`**（随宽度按截图固有比例自适应），不显式写高。
6. 不改 `PostDetailView` / `DetailMediaCarousel` / 轮播与视频的内部圆角实现。
