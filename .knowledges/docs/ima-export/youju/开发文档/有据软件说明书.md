## 一、引言

### 1.1 编写目的

本文档描述「有据——理性内容分享社区软件」V1.0 的整体设计，包括总体架构、功能模块、数据库结构、接口契约、安全策略、部署方案与操作说明，作为软件著作权登记、维护升级及协作开发的依据。

### 1.2 软件概述

「有据」是一款运行于 HarmonyOS NEXT 平台的原生移动应用，面向大众提供理性内容分享与深度交流服务。软件采用前后端分离架构：客户端基于 ArkTS/ArkUI（Stage 模型，API 24）原生开发，服务端基于 Node.js/Express/TypeScript，数据存储使用 MySQL（Prisma ORM），图片与视频存储于腾讯云 COS 并经 CDN 分发。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 帖子（Post） | 用户发布的内容单元，支持图文、纯文字、视频三种形态 |
| 圈子（Circle） | 以话题标签为核心的兴趣社区，可加入订阅 |
| 顶（Up） | 帖子点赞行为，同用户对同帖仅可顶一次 |
| 体裁（Genre） | 帖子类型：测评报告、避坑指南、实操教程、辩论投票 |
| 结构化字段 | 随体裁变化的补充信息，如测评报告的优点/缺点/推荐指数 |
| COS 预签名 | 腾讯云对象存储的临时直传凭证，客户端直传文件 |

### 1.4 运行环境

- 客户端：HarmonyOS NEXT（API 24 及以上），华为手机/平板
- 服务端：Linux（Ubuntu 20.04+），Node.js 18+，MySQL 8.0+，Nginx
- 存储：腾讯云 COS（图片/视频对象存储）+ CDN
- 依赖服务：华为账号服务（Account Kit）、华为推送服务（Push Kit）

## 二、总体概述

### 2.1 产品定位

「有据」致力于为有明确决策与学习需求的用户提供真实、硬核、有方法论的参考信息。与泛娱乐社区不同，软件强调内容结构化表达与理性讨论：用户可发布测评报告、避坑指南、实操教程与辩论话题，社区提供顶、收藏、事实补充评论、辩论投票等轻量化高信息密度的互动方式。

### 2.2 核心功能一览

| 功能模块 | 说明 |
|----------|------|
| 首页信息流 | 热榜/最新/推荐排序，标签筛选、下拉刷新、滚动分页 |
| 圈子订阅 | 30 个话题标签导航，圈子详情与加入订阅 |
| 内容发布 | 图文/纯文字/视频三种体裁，四步发布，草稿箱 |
| 内容详情 | 媒体轮播、全屏查看、视频播放、结构化字段、评论互动 |
| 搜索 | 关键词搜索，搜索历史与热搜榜 |
| 消息中心 | 评论/顶/收藏/关注/系统五类通知，未读角标 |
| 私信 | 一对一消息，已读未读、撤回、仅自己删除 |
| 个人主页 | 资料卡、作品/我赞过/我收藏、关注粉丝统计 |
| 内容治理 | 敏感词过滤、用户举报、管理员审核、拉黑/不喜欢 |
| 系统设置 | 深色模式、通知偏好、隐私设置、账号绑定、数据导出 |

### 2.3 技术栈

| 层次 | 技术 | 说明 |
|------|------|------|
| 客户端 | HarmonyOS NEXT + ArkTS + ArkUI | Stage 模型，API 24，声明式 UI |
| 服务端 | Node.js 18 + Express + TypeScript | REST API，统一响应与错误处理 |
| 数据库 | MySQL 8 + Prisma 5 | 21 张业务表，类型安全访问 |
| 对象存储 | 腾讯云 COS + CDN | 预签名直传，公网 viewUrl 读取 |
| 第三方 | Account Kit / Push Kit | 华为账号登录与推送通知 |
| 部署 | Docker Compose + Nginx | 容器化部署，TLS 反向代理 |

### 2.4 软件规模

客户端 ArkTS 与服务端 TypeScript 源码共约 3 万行；客户端页面 25 个、组件 43 个；服务端路由 18 组、服务模块 22 个；后端单元测试 85 例。

## 三、架构设计

### 3.1 系统总体架构

系统采用三层架构，前端与后端通过 HTTPS REST 接口通信，媒体文件经 COS 预签名直传：

[DRAW:ARCH]

- **表现层（客户端）**：HarmonyOS NEXT 应用，负责 UI 渲染、交互反馈与本地状态管理。页面（pages/）承载业务界面，组件（components/）复用卡片、弹窗、媒体播放等视图单元，工具库（utils/）封装登录态、主题、分享、图片压缩等能力。
- **服务层（后端）**：Express 应用，路由（routes/）定义 HTTP 入口，服务（services/）实现业务逻辑，中间件（middleware/）处理鉴权、限流、错误与敏感词，配置（config/）集中解析环境变量。
- **数据层**：MySQL 持久化业务数据，Prisma Client 提供类型安全查询；腾讯云 COS 存储图片/视频等非结构化文件。

### 3.2 客户端架构

客户端采用单 Ability 多页面架构：EntryAbility 作为唯一入口，加载 Index 主容器页；Index 内嵌底部 Tab（首页/圈子/发布/消息/我的），各 Tab 由独立组件承载；页面间通过 AppStorage 全局状态与路由栈切换。

客户端目录：`entryability/`（Ability 入口）、`pages/`（25 个业务页面）、`components/`（43 个可复用组件）、`services/api.ets`（HTTP 客户端 + 约 70 个领域 API）、`utils/`（登录态/主题/分享/图片/草稿等工具）、`models/types.ets`（数据模型）、`design/`（设计令牌与基础组件）。

### 3.3 服务端架构

服务端采用「路由-服务-中间件」分层：`index.ts`（启动入口，安全 fail-fast）、`app.ts`（Express 装配：helmet/限流/CORS/路由挂载）、`routes/`（18 组路由）、`services/`（22 个业务服务）、`middleware/`（auth/adminAuth/rateLimit/errorHandler）、`config/env.ts`（环境变量集中解析）、`utils/`（统一响应/脱敏视图/自定义错误）、`prisma.ts`（PrismaClient 单例）。

### 3.4 关键设计决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 登录体系 | 华为 Account Kit 授权码 → 后端换 token → JWT | 官方登录链路，安全合规 |
| 图片上传 | COS 预签名直传 | 客户端直传，后端不落盘 |
| 跨页通信 | AppStorage 全局状态 | API 24 下 router.getParams 失效 |
| 点赞同步 | 全局乐观更新仓库 | 跨页一致性与即时反馈 |
| 敏感词 | 自研 Aho-Corasick 自动机 | 无外部依赖，O(n) 检测 |
| 软删策略 | deletedAt 标记 | 数据可追溯，支持废纸篓恢复 |

## 四、业务流程设计

### 4.1 用户登录流程

[DRAW:LOGIN]

用户点击「华为账号登录」按钮，客户端通过 Account Kit 获取授权码（authorizationCode），调用后端 `POST /v1/auth/huawei/exchange`；后端用授权码向华为 OAuth 服务换取 access_token 与用户信息（unionID、昵称、头像），按 unionID 查找或创建用户，签发 JWT 并返回；客户端保存 token 与用户信息至持久化存储，此后请求携带 `Authorization: Bearer <token>`。

### 4.2 内容发布流程

[DRAW:PUBLISH]

发布流程四步：选体裁（图文/纯文字/视频）→ 填内容（标题、正文、媒体、结构化字段）→ 选标签（1~3 个）→ 预览发布。发布时客户端先请求预签名地址将媒体直传 COS，再调用 `POST /v1/posts`；后端对标题与正文执行敏感词检测，通过后入库置为待审核；管理员审核通过后进入公开信息流。中途可保存草稿至草稿箱。

### 4.3 内容审核与治理流程

[DRAW:MODERATION]

内容治理三道防线：第一道为敏感词前置过滤，发帖与评论经 Aho-Corasick 自动机检测，命中即拒绝并提示修改；第二道为用户举报，可对帖子和评论选择 7 类理由提交，同用户同内容仅可举报一次，达阈值自动下架并通知作者；第三道为管理员审核，对待审/被举报内容执行通过或拒绝，结果以系统通知告知作者与举报人。

### 4.4 信息流加载流程

[DRAW:FEED]

首页信息流按当前 Tab 排序模式（热榜/最新/推荐）与选中标签请求 `GET /v1/posts`，服务端经 accessControl 守卫过滤已拉黑、已不喜欢及隐私受限内容后返回分页列表；客户端渲染卡片，滚动到底自动加载下一页，下拉触发刷新。

### 4.5 辩论投票流程

辩论帖包含方案 A/B 及各自描述。用户点击投票，客户端调用 `POST /v1/posts/:id/debate-vote`；服务端依据 `DebateVote` 表唯一约束（userId+postId）保证每人仅投一次，返回两侧最新票数，客户端乐观更新即时刷新。

## 五、功能设计

### 5.1 首页信息流

首页布局：顶栏（Logo + 消息入口）+ 排序 Tab（热榜/最新/推荐）+ 标签导航栏 + 三列网格信息流。热榜按 24 小时内顶数降序，最新按发布时间倒序，推荐基于关注标签混排。帖子卡片统一 3:4 封面比例，展示标题、互动数据与作者。标签导航展示 30 个话题标签，点击进入圈子详情。

### 5.2 内容详情

详情页自上而下：作者信息区、标签与标题、媒体轮播（宽铺满高截断，支持全屏查看与长图滑动）、体裁标识与结构化字段、正文、互动操作栏（顶/收藏/评论/分享/举报/辩论投票）、评论区。视频帖子内嵌播放器并支持封面首帧。分享支持生成分享卡片（离屏 Canvas 绘制）、复制链接、系统分享三种方式。

### 5.3 发布器

发布器按体裁拆分为三个独立页面：图文发布页（选图、压缩上传、标题正文、结构化字段）、纯文字发布页（文字海报样式选择）、视频发布页（视频选择、首帧封面、上传）。三者在发布流程状态机（publishFlowStore）中统一管理体裁、标签与草稿状态，发布前进入预览页确认效果。

### 5.4 圈子与标签

圈子以话题标签为核心组织内容。用户可在标签导航栏与圈子详情页加入/退出圈子；加入后「关注流」按已关注标签混排推荐。圈子引导（CircleOnboarding）与轨道画布（CircleOrbitCanvas）提供可视化加入体验。

### 5.5 搜索

搜索面板支持关键词检索帖子标题与正文，搜索历史本地记录并支持清空；热搜榜按全站搜索频次聚合展示，点击热搜词直接发起搜索。

### 5.6 消息中心与私信

消息中心聚合评论、顶、收藏、关注、系统五类通知，服务端预渲染展示文案，未读红点提示。私信提供会话列表与聊天页，支持文本消息、已读未读、撤回与「仅自己删除」，私信权限受隐私设置（所有人/互关/关注者）约束。

### 5.7 个人主页

个人主页展示资料卡（头像、昵称、简介、背景图、关注/粉丝/获赞统计），下方分段展示作品、我赞过、我收藏。他人主页支持关注、拉黑、不喜欢；我的主页支持编辑资料、分享主页卡片。

### 5.8 设置与隐私

设置页覆盖：编辑资料、账号绑定（华为绑定/解绑）、通知偏好、隐私设置（帖子可见性、允许关注、私信策略）、深色模式与减弱动效、关于与退出登录。隐私政策与用户协议提供完整合规文本，首次启动展示隐私同意弹窗。

### 5.9 每日一帖

每日一帖在首页提供「每日精选」卡片组，由服务端按规则挑选当日推荐帖子，客户端以卡片堆叠展示，支持翻页浏览。

## 六、数据库设计

### 6.1 设计原则

数据库采用 MySQL 8 + Prisma ORM，共 21 张业务表。遵循原则：唯一约束保证幂等（顶/收藏/关注/举报/投票防重复）；软删标记保留历史（deletedAt）；轻量表仅存标量外键避免级联复杂度；时间字段统一 UTC 存储。

### 6.2 数据模型总览

[DRAW:ER]

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| User | 用户表 | openId/unionID（双唯一登录标识）、昵称、头像、隐私政策版本 |
| Post | 帖子表 | 标题、正文、封面、图片/视频、体裁、标签、结构化字段、计数、状态 |
| Comment | 评论表 | 内容、父评论、是否事实补充、状态、举报数 |
| Up / CommentUp | 顶记录 | userId+postId / userId+commentId 唯一 |
| Bookmark | 收藏记录 | userId+postId 唯一 |
| Tag | 标签表 | 名称唯一、emoji、分类、使用/关注计数 |
| UserFollowTag | 圈子订阅 | userId+tagName 唯一 |
| SearchHistory | 搜索历史 | 用户+关键词+时间索引 |
| UserBinding | 账号绑定 | userId+provider 唯一，占用校验 |
| Notification | 通知表 | 类型、触发者、内容、已读、帖子关联 |
| PushToken | 推送 Token | 设备 Token 全局唯一 |
| MediaDeletionTask | 媒体删除任务 | 异步删除 COS 对象，失败重试 |
| Follow | 关注关系 | followerId+followingId 唯一 |
| Report | 举报记录 | 举报人+目标类型+目标唯一，状态流转 |
| NotificationPreference | 通知偏好 | 五类通知开关 |
| Blocklist / Dislike | 拉黑 / 不喜欢 | 关系唯一，双向 / 推荐流过滤 |
| PrivacySettings | 隐私设置 | 可见性/关注/私信策略 |
| DebateVote | 辩论投票 | userId+postId 唯一，A/B 选择 |
| Message / MessageDeletion | 私信 / 删除记录 | 会话索引，仅自己删除 |

### 6.3 核心关系说明

- User 1:N Post/Comment/Up/Bookmark/UserFollowTag/SearchHistory/UserBinding/PushToken
- Post 1:N Comment/Up/Bookmark/DebateVote；Comment 1:N CommentUp
- 评论随帖子级联删除（onDelete: Cascade）
- 计数类字段（upCount/bookmarkCount/commentCount/reportCount）冗余在帖子表，写入事务内维护

## 七、接口设计

### 7.1 通用规范

所有接口统一前缀 `/v1`，响应包裹 `{ code, data, message }`；code=0 表示成功，非 0 为业务失败；鉴权失败返回 HTTP 401。列表接口统一分页参数 page/limit（默认 20，最大 50），响应携带 pagination。需登录接口在请求头携带 `Authorization: Bearer <token>`。

### 7.2 错误码

| code | HTTP | 含义 |
|------|------|------|
| 0 | 200 | 成功 |
| 400 | 400 | 参数错误 / 敏感词命中 |
| 401 | 401 | 未登录 / token 过期 |
| 403 | 403 | 无权限 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 冲突（重复顶/收藏/举报等） |
| 500 | 500 | 服务内部错误 |

### 7.3 接口清单

| 模块 | 接口 | 说明 |
|------|------|------|
| 登录 | POST /v1/auth/login | 登录获取 token（开发桩） |
| 登录 | POST /v1/auth/huawei/exchange | 华为授权码换 token（真实 Account Kit） |
| 用户 | GET/PUT /v1/auth/me | 当前用户信息 / 更新资料 |
| 用户 | GET /v1/users/:id | 用户主页信息（含关注关系与隐私过滤） |
| 帖子 | GET /v1/posts | 信息流列表（分页+标签+排序） |
| 帖子 | GET /v1/posts/:id | 帖子详情 |
| 帖子 | POST /v1/posts | 发布（进入待审核） |
| 帖子 | DELETE /v1/posts/:id | 删除（仅本人） |
| 帖子 | GET /v1/posts/following | 关注流 |
| 帖子 | GET /v1/posts/daily | 每日一帖 |
| 帖子 | POST /v1/posts/:id/debate-vote | 辩论投票 |
| 帖子 | POST /v1/posts/:id/report | 举报帖子 |
| 评论 | GET/POST /v1/posts/:id/comments | 评论列表 / 发布评论（敏感词检测） |
| 评论 | DELETE /v1/comments/:id | 删除评论 |
| 评论 | POST /v1/comments/:id/report | 举报评论 |
| 互动 | POST/DELETE /v1/posts/:id/up | 顶 / 取消顶 |
| 互动 | POST/DELETE /v1/posts/:id/bookmark | 收藏 / 取消收藏 |
| 标签 | GET /v1/tags | 全部标签 |
| 标签 | POST /v1/tags/:name/follow | 加入圈子 |
| 搜索 | GET /v1/search | 搜索帖子 |
| 搜索 | GET /v1/search/hot | 热搜词 |
| 上传 | POST /v1/upload/token | 获取 COS 预签名直传凭证 |
| 消息 | GET /v1/messages | 会话列表 |

## 八、安全设计

### 8.1 身份认证与鉴权

客户端经华为 Account Kit 获取授权码，后端换取 access_token 与用户身份后签发 JWT；JWT 设置有效期并由服务端校验签名与用户状态（封禁/注销后 token 失效）。敏感接口经 auth 中间件解析 token，管理员接口额外经 adminAuth 校验白名单。

### 8.2 网络安全

- **helmet**：设置安全 HTTP 头（CSP、X-Frame-Options、HSTS 等）
- **CORS 白名单**：仅允许配置的前端来源访问
- **全局限流**：全站按 IP 限流，登录与上传接口专项限流
- **HTTPS 强制**：生产环境校验配置，强制 TLS 传输

### 8.3 内容安全

- **敏感词过滤**：自研 Aho-Corasick 自动机，加载 595 条敏感词（通用 + 性别对立），发帖与评论前置检测，兼容全角、大小写、零宽字符变形
- **举报机制**：7 类举报理由，同用户同内容幂等，达阈值自动下架
- **人工审核**：管理员审核台对待审与举报内容复核，结果通知相关方且不泄露举报人身份

### 8.4 数据安全与隐私

- 用户资料输出统一经脱敏视图（userView），仅暴露必要字段
- 隐私政策版本与同意时间留存（PIPL 合规追溯）
- 图片/视频走 COS 预签名 URL，私有桶访问经鉴权；密钥仅在服务端环境变量，绝不下发客户端
- 数据导出接口支持用户下载个人数据

### 8.5 输入与幂等安全

- 所有入参经校验，业务错误统一返回结构化 message
- 顶/收藏/关注/举报/投票以数据库唯一约束保证幂等
- 删除采用软删（deletedAt），媒体删除经异步任务队列解耦并支持重试

## 九、部署设计

### 9.1 部署架构

生产环境采用 Docker Compose 编排三容器：MySQL 8（数据存储）、API 服务（Node.js 应用）、Nginx（TLS 反向代理与静态资源）。API 与数据库通过内部网络互通，Nginx 对外暴露 443 端口终止 TLS。

### 9.2 域名与反向代理

对外域名 api.youju.chat 的 A 记录指向服务器，Nginx 主 server 块将 HTTPS 请求反代至 API 容器，配置 CORS 白名单与媒体路径代理；COS 桶配置 CORS 规则允许前端域名直传与读取。

### 9.3 环境变量与启动

配置集中解析于 config/env.ts，生产缺失关键密钥（JWT_SECRET/CORS_ORIGIN 等）时启动即拒绝（fail-fast）。部署使用独立 .env.production 文件，与开发环境隔离。

### 9.4 数据备份与上线流程

部署目录内置 mysqldump 备份脚本，每日定时导出并保留最近 14 天。上线流程：本地开发 → 单元测试全绿 → 构建产物推送服务器 → Docker 重建 → /health 健康检查 → 真机验证；数据库结构变更经 prisma db push 同步。

## 十、操作手册

### 10.1 安装与启动

用户从应用市场安装「有据」或真机安装 HAP 包，首次启动展示隐私政策同意弹窗，同意后进入首页。服务端部署后访问 /health 返回 {"ok":true} 即正常。

### 10.2 登录

点击「我的」Tab → 「华为账号登录」→ 系统弹出华为账号授权页 → 同意后自动完成登录并返回应用。

### 10.3 发布内容

点击底部 Tab 中央「发布」→ 选择图文/纯文字/视频 → 填写标题与正文、上传媒体、补充结构化字段、选择 1~3 个标签 → 预览 → 提交发布。内容经审核通过后出现在信息流。

### 10.4 互动操作

- 顶：帖子卡片或详情页点击顶图标，再次点击取消
- 收藏：详情页点击收藏，收藏内容见「我的-我收藏」
- 评论：详情页评论区输入发送，可标记「事实补充」
- 分享：详情页分享按钮，支持分享卡片/复制链接/系统分享
- 举报：详情页菜单或评论长按选择举报，选理由提交
- 辩论投票：辩论帖详情页选择方案 A/B 投票，投后可查看实时票数

### 10.5 圈子订阅

首页标签导航栏点击标签进入圈子详情，点击「加入圈子」订阅；已订阅内容在首页关注流聚合展示。

### 10.6 消息与私信

「消息」Tab 查看通知列表，点击进入对应内容；私信入口在他人主页，点击「发私信」进入聊天页发送文本消息，私信权限受隐私设置约束。

### 10.7 个人资料与设置

「我的」Tab → 编辑资料（昵称/头像/简介/背景图）→ 设置页配置通知偏好、隐私、深色模式、账号绑定、数据导出；点击「退出登录」清除本地登录态。

### 10.8 管理员审核

管理员登录后进入审核台：查看待审帖子与举报列表，对内容执行「通过」或「拒绝」（可附原因），操作结果自动通知作者与举报人。
