# 分段栏滑块跟手联动（Swiper 拖动/吸附 1:1 跟手）— 实施计划

## 一、概述

**问题**：首页（及"我的"、消息页）内容区改为 Swiper 分页后，左右滑动页面时，分段栏滑块只在滑动"落定"后才移动（由 `onChange` 驱动整数索引切换），拖动过程中滑块完全不动——没有跟上手势。

**目标**：滑动过程中滑块 1:1 跟着手指移动，松手后跟着吸附动画同步到位（像华为应用商店/iOS 分段栏那样连续跟手）；点击分段切换时仍保留现有的弹性动画（springInteract 回弹）。

**改动面**：3 个文件（设计系统）+ 3 个页面（接 Swiper 回调），均为小改。

---

## 二、现状分析（已核实）

### 2.1 滑块当前的运动来源

- [SegmentedControl.ets](file:///Users/itxiaobai/HarmonyProject1/entry/src/main/ets/design/components/SegmentedControl.ets#L204-L216) 把 `activeIndex()`（= `selectedIndex` 整数，来自 `$feedIndex`/`$tabIdx`/`$dmTabIndex` 双向绑定）传给 [SharedSlide](file:///Users/itxiaobai/HarmonyProject1/entry/src/main/ets/design/motion/SharedSlide.ets#L38-L41)。
- `SharedSlide.selectedOffset()` 直接用 `selectedIndex * slotWidth()` 计算位移，**数学上已支持浮点索引**（未取整），只是目前没人喂浮点值。
- 整数索引变化时经 `.animation({ curve: springInteract })` 做弹性补间 → 所以现状是"松手后（onChange 触发）滑块才弹性滑过去"。

### 2.2 可用的官方逐帧回调（已核实语义）

- `Swiper.onContentDidScroll(selectedIndex, index, position, mainAxisLength)`：
  - 官方文档：**滚动过程中按帧回调视窗内所有页面**（拖动与吸附动画全程，API 12+，本 SDK 可用，见 `swiper.d.ts` L2433-L2456）。
  - `selectedIndex`=动画开始前选中的页；`position`= **index 页相对主轴起始位置（selectedIndex 页起始位置）的移动比例**（无量纲比值）。
  - ⇒ **连续（视口）索引 = `index - position`**。已验证自洽：向右/向左滑、静止态下，当前页与相邻页回报计算出的连续索引一致（静止时恒等于整数索引）。
  - 只处理 `index === selectedIndex` 这一路回报即可（最简、单一来源）。
- `Swiper.onAnimationEnd(index)`：吸附动画结束时触发（`swiper.d.ts` L2315-L2340）。
- `Swiper.onChange`：**"新索引被选中时触发，动画不一定结束"**（`swiper.d.ts` L2134-L2136）——即吸附动画**开始**时就触发，因此**不能在 onChange 里清除跟手值**（会造成滑块抢跑、与内容脱节）。

## 三、改动方案

### 3.1 [motion.ets](file:///Users/itxiaobai/HarmonyProject1/entry/src/main/ets/design/tokens/motion.ets#L4-L27) — 新增零时长 token

`MotionTokens.instant = 100`（微软"减动效"用的快速补间）**不能**用于逐帧跟手（每帧重定向 100ms 补间 = 拖尾滞后）。在 `instant` 后新增：

```typescript
// 逐帧跟手：不做补间、属性即时生效（Swiper 联动等逐帧驱动的连续位移，避免滑块滞后于手势）
static readonly none: number = 0;
```

### 3.2 [SharedSlide.ets](file:///Users/itxiaobai/HarmonyProject1/entry/src/main/ets/design/motion/SharedSlide.ets) — 跟手时不补间

新增私有判定（浮点 = 滚动中的连续位置；整数 = 点击切换）：

```typescript
// 逐帧跟手：浮点索引（Swiper 拖动/吸附过程中的连续位置）不做补间，逐帧即时贴合手势；
// 整数索引（点击切换）保留弹性动画（springInteract 过冲回弹）
private isTracking(): boolean {
  return Math.abs(this.selectedIndex - Math.round(this.selectedIndex)) > 0.001;
}
```

修改 build 内唯一的 `.animation(...)`（L62-L65）：

```typescript
.animation({
  duration: (this.shouldReduceMotion() || this.isTracking()) ? MotionTokens.none : MotionTokens.base,
  curve: this.shouldReduceMotion() ? MotionCurves.standard : MotionCurves.springInteract,
})
```

说明：按压缩放 `pressed` 共用同一组动画参数——跟手期间手指在内容区（不在分段栏上），`pressed` 不变，无可见影响；松手一帧内缩放瞬时复位，位移速度很快，观感无差异。

### 3.3 [SegmentedControl.ets](file:///Users/itxiaobai/HarmonyProject1/entry/src/main/ets/design/components/SegmentedControl.ets) — 接收跟手位置

属性区新增（放在 `@Prop immersive` 附近）：

```typescript
// Swiper 联动跟手位置：滚动（拖动/吸附）中由页面喂入的连续（浮点）索引，1:1 跟手；
// -1 表示未在滚动（回退 activeIndex()，点击切换仍走弹性动画）
@Prop slidePosition: number = -1;
```

`SharedSlide({...})` 调用处（L204-L216）改一行：

```typescript
selectedIndex: this.slidePosition >= 0 ? this.slidePosition : this.activeIndex(),
```

文案强调仍按 `activeIndex()`（整数）切换，本次不动。

### 3.4 三个页面 — 接 Swiper 回调 + 点击回写

三个页面同一套改法（以 HomeTab 为例，替换为各页常量/状态名）：

**① 新增状态**（挨着现有分段索引状态，如 HomeTab 的 `feedIndex`）：

```typescript
// 分段滑块跟手位置：Swiper 滚动（拖动/吸附）中喂入的连续索引；-1 = 未滚动
@State slidePosition: number = -1;
```

**② Swiper 链尾追加两个回调**（`.onChange(...)` 之后）：

```typescript
.onContentDidScroll((selectedIndex: number, index: number, position: number, _mainAxisLength: number): void => {
  // 只取当前选中页的回报（selectedIndex 在整段滚动中恒定）：
  // 连续索引 = index - position，官方语义 position 为 index 页相对主轴起始的位移比例
  if (index !== selectedIndex) {
    return;
  }
  const continuous: number = selectedIndex - position;
  this.slidePosition = Math.max(0, Math.min(FEED_SEGMENTS.length - 1, continuous));
})
.onAnimationEnd((): void => {
  // 吸附收尾：已回到整数位才清除跟手覆盖（回落整数索引，数值一致无跳变）；
  // 中途被打断的动画保持浮点覆盖，避免滑块闪跳回旧位置
  if (Math.abs(this.slidePosition - Math.round(this.slidePosition)) < 0.01) {
    this.slidePosition = -1;
  }
})
```

**③ 分段栏加一个 prop**：

```typescript
SegmentedControl({
  items: FEED_SEGMENTS,
  selectedIndex: $feedIndex,
  slidePosition: this.slidePosition,   // 新增
  ...
})
```

**④ 点击切换时回写整数索引**（防止残留浮点值卡住滑块；不能放进 `switchFeed`/`onTabChange`——那里同时被 Swiper 的 onChange 调用，会在吸附开始时抢跑）：

```typescript
onSelect: (idx: number): void => {
  this.slidePosition = idx;           // 新增：点击立即落整数位（弹性动画由 SharedSlide 整数分支承担）
  this.switchFeed(FEED_MODE_IDX_MAP[idx]);   // 各页原有调用
},
```

三页对应关系：
- HomeTab：`FEED_SEGMENTS.length`=3，`switchFeed(FEED_MODE_IDX_MAP[idx])`
- ProfilePage：`PROFILE_SEGMENTS.length`=4，`this.onTabChange(idx)`（只改主分段栏 L975-L982；收藏子分段不动）
- MessagePage：`MESSAGE_SEGMENTS.length`=2，`this.switchDmTab(idx)`

## 四、假设与决策

1. **`position` 符号**：按官方"index 页相对主轴起始的移动比例"取 `index - position`（已用静止/左滑/右滑三种工况推演自洽）。真机若发现滑块反向（跟手方向相反），只需把三个页面里的 `selectedIndex - position` 改为 `selectedIndex + position`（单点、各页一行）。
2. **不做清单**：不插值文案强调（文字仍按整数索引切换）；不改其他无 Swiper 的分段栏；不加新组件 API 的公开文档。
3. **性能**：`slidePosition` 仅被 `SegmentedControl` 的 props 读取，ArkUI 部分更新只会刷新分段栏/滑块节点，不会重建 Swiper 页面内容（逐帧写 @State 是安全的）。
4. **每日一帖卡堆**：卡堆自身 PanGesture 优先消费横滑，Swiper 不滚动 ⇒ 不触发跟手回调，行为不变。
5. **减动效**：`reduceMotion` 开启时滑块本就瞬时，与跟手规则叠加仍正确（都走 0ms）。

## 五、验证步骤

1. **编译**：`hvigorw assembleHap`（与现有构建命令一致）→ BUILD SUCCESSFUL，无新增 ERROR/WARN。
2. **真机/模拟器手感验收**（首页为主）：
   - 按住内容区左右拖动**不松手**：滑块 1:1 跟随手指（无滞后、无跳变）。
   - 松手：滑块跟随吸附动画与页面内容**同时**到位。
   - 快速甩动后松手：同样跟手、无抢跑。
   - 边界拖动（推荐页再往右 / 每日一帖再往左）：滑块跟随偏移后回弹归位。
   - 点击分段：滑块仍走弹性动画（springInteract 回弹），与改动前一致。
   - 每日一帖卡堆拖拽：滑块不动（卡堆手势优先，符合预期）。
3. **回归**：消息页（2 段）、我的页（4 段）同样跟手；底部 Tab 栏（SharedSlide 另一消费方）切换动画无变化；CircleDetail/SearchResult/EditProfile 分段栏点击动画无变化。
