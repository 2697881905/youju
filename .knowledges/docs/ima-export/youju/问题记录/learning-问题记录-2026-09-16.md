# 增量学习产出 · 问题记录（2026-09-16 首次全量，19 篇）

## 2026-09-15-edit-tool-large-file-structure-corruption（agent-ops / pitfall）
- 事实：Edit 工具改大文件（数百行 ArkTS）易产生代码块重复与方法结构破坏；破坏后表现为构建失败而非编辑报错；属工具操作失败模式而非代码逻辑缺陷。
- 决策：大文件改动优先小步多次 + 改完立即编译验证；不信任单次大范围替换。
- 模式：编辑大文件后**必须**跑一次 PreviewBuild，把"能编译"作为编辑完成的判据。

## 2026-09-15-harmonyos-permission-reason-field（build-env / pitfall）
- 事实：module.json5 的 requestPermissions 缺 reason 字段会被 AGC 审核系统直接拦下；INTERNET 权限同样需要；string.json 需配套说明文案。
- 决策：所有权限声明统一补齐 reason + usedScene，纳入发版前检查项。
- 模式：提审前按「权限→reason→文案→签名→图标」顺序逐项核对。

## 2026-09-15-arkts-strict-mode-constraints（build-env / pitfall）
- 事实：ArkTS 严格模式禁索引签名/无类型字面量/对象展开/解构/函数型 @Prop；违反在编译期报 10505001 等错误。
- 决策：数据模型统一用具名 interface，动态取值用 Map/switch 替代 obj[key]。
- 模式：写 ArkTS 前先过一遍「六禁令」清单，能省一轮编译返工。

## 2026-09-15-arkui-motion-design-token-system（architecture / decision）
- 事实：动画参数散落各处会导致手感漂移；集中为令牌后可全局一致；硬编码 duration/curve 是主要漂移源。
- 决策：动画参数统一进 MotionTokens，禁止组件内硬编码时长曲线。
- 模式：新增动效先问「参数是否已存在令牌」，否则先补令牌再写动效。

## 2026-09-15-unified-api-wrapper-bypass-risk（architecture / pitfall）
- 事实：绕过统一 request 封装直连 http.createHttp 会丢失 401 拦截与全局错误解析；uploadChatMedia 曾走旁路。
- 决策：所有网络请求必须走统一封装，上传类也不许例外。
- 模式：CR 检查项「是否出现 createHttp/裸 fetch」= 一票否决。

## 2026-09-15-arkui-shared-element-transition / 2026-09-15-harmonyos-shared-transition-pattern（technique）
- 事实：sharedTransition 需源页与目标页挂同一 id；无媒体卡片不挂 id 回退现页转场；只动 transform/opacity。
- 决策：采用「共享动势 + 分层进入」而非 geometryTransition（项目全 router.pushUrl，跨页 geometryTransition 不可用）。
- 模式：一镜到底转场三要素=同 id、仅 transform/opacity、无媒体回退。

## 2026-09-16-arkui-ui-ux-interaction-audit-checklist（workflow / methodology）
- 事实：交互审查关注缺失态（加载/空/错误/禁用）、模式一致性、无障碍三类缺口。
- 决策：把交互完整性检查做成清单，逐页走查而非凭感觉。
- 模式：每个页面四态自查：加载中 / 空数据 / 错误 / 禁用。

## 2026-09-15-agc-review-config-checklist（workflow / methodology）
- 事实：AGC 打回集中在权限 reason、签名产物形态、版本号一致、包内残留内网 IP 四类。
- 决策：用 check-release.sh 做发版前形态检查（buildMode 还原、release 产物、签名、版本、无内网 IP）。
- 模式：提审前跑脚本 + unzip 查包内字符串双保险。

## 2026-09-15-empty-catch-block-audit（coding-pattern / methodology）
- 事实：空 catch 与 fire-and-forget async 会吞掉错误，故障无日志可查。
- 决策：catch 必须至少打日志；async 调用必须 catch。
- 模式：审计时搜索 `catch {` 空体与无 catch 的异步调用。

## 2026-09-16-arkui-state-variable-ui-render-gap（pitfall）
- 事实：定义了 @State 却漏了 build 中的渲染分支 → 状态存在但界面无反馈；错误态因此不可见。
- 决策：每加一个状态变量，同步补渲染分支（含错误分支）。
- 模式：状态变量与渲染分支成对检查，禁止「只存不显」。

## 2026-09-16-arkui-input-maxlength-validation-gap（pitfall）
- 事实：输入框漏 maxLength 或自定义组件默认过大 → 超长文本入库与 UI 溢出。
- 决策：所有输入显式设 maxLength，与后端字段长度对齐。
- 模式：输入类组件清单化核对 maxLength + 校验提示。

## 2026-09-15-arkui-image-error-handling（pitfall）
- 事实：Image 不绑 onError/alt 时加载失败呈白屏；URL 非空但失效同样触发。
- 决策：Image 统一 onError + alt + 占位 backgroundColor。
- 模式：图片组件三件套：onError、alt、占位底色。

## 2026-09-15-harmonyos-component-timer-cleanup（pitfall）
- 事实：setTimeout/setInterval（含动画过渡用的）未在 aboutToDisappear 清理会泄漏并在返回后触发。
- 决策：组件内所有定时器登记并统一在 aboutToDisappear 清理。
- 模式：新增定时器即登记清理清单（长按、防抖、动画过渡都算）。

## 2026-09-16-arkui-dark-mode-hardcoded-color-pitfall（pitfall）
- 事实：深色写死色值导致元素隐身；对比度不足会被审核打回。
- 决策：颜色一律走 ColorTokens/资源色，深浅两套成对维护。
- 模式：新增文字/图标前用 WCAG 公式验对比度（辅助≥4.5，图标≥3.5）。

## 2026-09-15-arkui-transition-effect-staggered-enter（technique）
- 事实：整页同帧入场显生硬；TransitionEffect 分层错峰更自然。
- 决策：列表/页面入场采用分层 stagger，参数取自 MotionTokens。
- 模式：入场动效 = 分层 + 错峰 + 令牌参数。

## 2026-09-15-arkui-spring-motion-card-deck（technique）
- 事实：单一弹簧刚度让卡堆手感呆板；多层独立弹簧 + 视差才有层次。
- 决策：跟手/离手分别配置 springMotion 参数。
- 模式：卡堆交互 = 多层弹簧 + 视差深度。

## 2026-09-15-arkui-v1-plain-getter-dropped（pitfall）
- 事实：ArkUI V1 编译器会丢弃组件的 plain getter，导致运行时崩溃。
- 决策：组件属性不要用纯 getter，改为显式属性或在 build 内取值。
- 模式：@Builder 传 getter 给 @Prop 也断响应式 → 一律内联读 @State。
