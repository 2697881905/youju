- 实现华为 AccountKit 登录全链路，覆盖前端授权码获取、服务端 Token/UnionID 兑换、JWT 会话签发与账号体系落库，真机端到端验证通过，支撑 AGC 上架场景下的合规账号能力。
- 建立媒体上传与内容安全机制，包括腾讯云 COS 预签名 URL 客户端直传、视频 50MB 双重校验、接口限流、幂等控制与敏感词过滤，规避服务端流量中转与 UGC 滥用风险。
- 搭建单机生产部署体系，基于 Docker Compose + Nginx 实现后端容器化发布、MySQL 数据持久化、SSL 与域名接入，完成 ICP 备案，达成可上线状态。

**项目难点与解决方案**

1. **沉浸式布局疑难**：针对沉浸式全屏下列表滚动终点被底部安全区钳制、官方扩展方案（expandSafeArea / ignoreLayoutSafeArea）均无效的问题，通过对照实验定位 Scroll 容器免疫此问题的布局机制，确立“全屏壳内列表一律用 Scroll”的容器选型规范并批量迁移多个页面，彻底解决末行内容滚不到底的问题。
2. **跨页状态同步**：针对 API 24 路由参数接口弃用返回空、页面返回不重跑生命周期导致详情页点赞/收藏与列表页状态脱节的问题，设计“AppStorage 中转 + @StorageLink/@Watch 监听 + 单例 store 共享”的三层同步方案，保障高频互动操作跨页实时一致。
3. **华为登录与签名链路打通**：针对 Invalid clientId、client_secret 密钥区域混淆、调试证书指纹未登记 AGC、真机/release 签名配置错误（9568320/9568332）等连环阻塞，逐错误码排查定位，打通“授权码 → 服务端换 Token → UnionID 落库 → JWT 会话”的 OAuth 授权码模式全链路。

## 三、技术难题与解决方案（面试深挖核心，重点背）

### 难题 1：ArkTS 严格模式的语法约束 ⭐️体现学习能力
- **问题**：ArkTS（V1 严格模式）比 TypeScript 严格得多：禁止索引签名、禁止无类型对象字面量、禁止对象展开/解构、`@Builder` 函数内不能声明变量、`Text` 组件没有 `minWidth` 属性。
- **解决**：用具名 `interface` 替代松散对象；用 `Map` 或 `switch` 替代 `obj[key]` 动态取值；把 `@Builder` 内的逻辑抽成私有方法；用 `constraintSize({minWidth})` 替代不存在的 API。
- **讲法**：「这不是查文档就能过的坎，是从 Web TS 思维切到受限声明式 UI 思维的重构，我总结了一整套替代写法清单，后续写新页面零返工。」

### 难题 2：跨页面状态同步（框架路由机制的理解）⭐️高频追问
- **问题**：三个连环坑——`router.getParams()` 在 API 24 已弃用且返回空；`router.back()` 返回后不重新执行 `aboutToAppear`；Tab 页的 `onPageShow` 不触发。导致"详情页点赞 → 返回列表不同步"这类问题。
- **解决**：跨页参数统一走 `AppStorage`（如 `detailPostId`）；依赖刷新的页面用 `@StorageLink` + `@Watch` 监听；点赞态等高频共享状态抽成单例 store（likeStore）；列表项细粒度更新用 `@Observed` + `@ObjectLink`。
- **讲法**：「本质是搞清楚鸿蒙状态管理的数据流向——UI 不持有状态，状态放全局可观察层，页面只是订阅者。」

### 难题 3：沉浸式全屏下滚动被安全区"钳制" ⭐️最有含金量，独家疑难
- **问题**：沉浸式全屏壳里，`List`/`WaterFlow`/`Grid` 滚动终点被底部导航条安全区钳制，末行内容滚不到物理底部，露出一条底色横带；`expandSafeArea`（只扩绘制）和 `ignoreLayoutSafeArea`（布局延伸）都无效。
- **解决**：系统性排查后定位到 **Scroll 容器天然免疫此问题**，于是确立"沉浸式壳内列表一律用 Scroll"的容器选型约定（双列瀑布流 = 两个 Column + layoutWeight），批量迁移多个页面，并加了尾部占位 Blank 垫底 + `constraintSize({minHeight:'100%'})` 贴顶。
- **讲法**：「先做对照实验（Scroll 正常 / List 异常）缩小怀疑范围，再从布局机制推因，最后沉淀成团队规范——这就是从'能跑'到'懂为什么'的过程。」

### 难题 4：华为账号登录全链路打通 ⭐️体现排查能力
- **问题**：连环报错——登录按钮 `Invalid clientId`（module.json5 缺 metadata.client_id 配置）；后端换 token 报密钥错误（错拿了「客户端ID」区的 API 密钥，正确的是 OAuth 2.0 凭据区 64 位 hex secret）；调试证书指纹未在 AGC 登记被拒；真机包报 9568320（未挂签名配置）/ 9568332（release Profile 不含本地真机 UDID）。
- **解决**：逐个错误码定位，按「前端拿 authorizationCode → 后端持 client_id + secret 换 token → 拉 UnionID/昵称/头像落库 → 签发 JWT」重整链路，登录接口耗时 ~470ms 全真机验证通过。
- **讲法**：「OAuth 授权码模式的标准流程我是靠这次实践真正吃透的——前端只拿 code，密钥永远不出服务端。」

### 难题 5：媒体上传架构演进 ⭐️体现架构意识
- **问题**：早期把图片 base64 存数据库，DB 膨胀、响应体巨大，属于典型反模式。
- **解决**：改为「服务端签发 COS 预签名 URL → 客户端直传腾讯云 COS → DB 只存短 URL」；读取用 1 年期预签名 viewUrl 解决私有桶 403；对象存储换桶时写脚本（putObjectCopy）全量迁移；补齐 COS 桶的 CORS 规则。
- **讲法**：「我会主动说这是踩过坑后自我纠正的——能识别反模式并给出正确架构，比从来没犯错更有说服力。」

### 难题 6：安全与合规（AGC 审核打回整改）⭐️体现工程素养
- **问题**：AGC 审核打回——深色模式下三级辅助文字对比度不达 WCAG AA 标准；此外社区类应用天然面临内容安全要求。
- **解决**：深色色板整体提亮并用 WCAG 公式脚本逐级验算（secondary > tertiary > quaternary 层级有序）；确立"新增文字一律走主题色 token、禁止硬编码灰"的规范；后端落地 JWT / helmet / CORS 白名单 / 接口限流 / 幂等 / 敏感词过滤，拉黑名单与推荐流双向过滤。
- **讲法**：「无障碍和内容安全不是加分项，是上架的硬门槛——我把它们当成产品的一部分来设计。」

### 难题 7：生产环境部署 ⭐️体现全栈闭环
- **要点**：Docker Compose 编排 MySQL + 后端 + Nginx；`prisma db push` 同步生产 schema；开发/生产环境变量隔离（CORS_ORIGIN、BACKEND_PUBLIC_URL）；域名 + SSL 证书 + ICP 备案。
- **讲法**：「部署让我补齐了最后一公里：容器、反向代理、证书、备案，这条链路走通一遍比看十篇教程有用。」

### 难题 8：构建工具链的坑 ⭐️细节真实感
- **要点**：改 `main_pages.json` 后 hvigor daemon 缓存旧页面表，需杀进程 + 清缓存重建；DevEco Run 不重装旧 HAP，改源码必须 Build Hap + 卸载重装才能生效；8 位色值是 `#AARRGGBB`（alpha 在前），与 CSS 的 `#RRGGBBAA` 相反。
- **讲法**：面试官问"开发中印象最深的细节"时用，证明是真上手写过，不是背概念。

## 五、注意事项（专科大三身份加分策略）

1. **诚实边界**：可以写"独立开发"（事实如此），但不要暗示商业团队项目；AI 辅助开发在 2026 年是正常工程实践，重点是**每个技术细节你都能亲自讲清**——讲不清的条目删掉。
2. **数字真实**：33 页面 / 90+ 接口 / ~3 万行均已核实；不要夸大用户量或编造上线数据。
3. **准备演示**：带真机或录屏（登录 → 发布 → 点赞 → 搜索完整走一遍），面试现场演示是最强背书。
4. **衔接岗位**：投鸿蒙岗突出 ArkUI 疑难攻坚；投前端岗突出"声明式 UI + 状态管理 + 类型系统"的迁移能力（React/Vue 思维相通）；投后端岗突出 RESTful 设计 + 安全中间件 + 部署。
5. **一句话人设**：「我不是只跟着教程做过 demo 的学生——我独立交付了一个从登录、发布、审核到部署都完整的产品。」
