### 更正：Pocket 2 测不出 md 档（原清单前提有误）

我一度把 1136×2690 当成「外屏 = sm」，让你去展开内屏——错了。实测这台机只有两块显示面：
`1136×2690`（主屏，ON）与 `340×340`（圆形副屏，OFF）。**Pocket 2 是竖折机，展开后的主屏除以密度
3.125 = 363.5vp，本身就是 sm**；md 要 600–840vp，只有 Mate X7（内屏 707.2vp）或平板才有。
所以 `guest-convert-bar-patch.md` §3 第 6 项写的「内屏（md，3–4 列）」是做不到判据，已在该文档就地更正。

md 改由代码侧收口：引导条是 `Row`（列容器）之前的满幅兄弟节点，`feedColIndexes()` /
`feedColCount()` 与 ForEach key `seg+'-feed-'+colIdx+'-'+post.id` 都不引用它，列数 2→3 不改变其排布
语义；md 下 `layoutWeight(1)` 的文字列更宽，主标题只会**减少**换行，不新增截断面。残余风险只剩
「3 列整体观感」，与引导条无关。**日后要真测 md，需要平板或 Mate X7 模拟器。**

## 4. 留给你拍板的行为修复（我按「无法验证的代码不合入」没提交）

### 4.1 游客点互动是「先假成功再打回」，且不拉登录页

现状（4 处同一形状）：`PostCard.ets:125` 顶帖、`PostDetailView.ets:703` 顶帖、`:752` 收藏、`:1309` 评论。全部先乐观更新 → 等 401 → 回滚 → toast「操作失败，请先登录」，**但不跳登录页**。而同屏的评分胶囊点星就直接 `ensureLogin()`（`PostDetailView.ets:1896`）。游客的第一次尝试观感是"按钮闪一下然后报错"，且与引导条「登录后可收藏、顶帖」并置时最刺眼。

建议补丁（4 处各加开头几行）：

```ts
async onLike(): Promise<void> {
  const id: number | undefined = this.postId();
  if (id === undefined) { return; }
  // 游客不做起伏式假动作：直接按引导条的承诺送他去登录页
  if (getToken() === '') { await ensureLogin(); return; }
  const willLike: boolean = !this.liked;
  ...
```

需要 import：`getToken, ensureLogin` from `../utils/auth`（PostCard 目前可能没引）。

**为什么留给你**：`PostCard` 挂在 `HomeTab` 的 HdsNavigation 内容区里，而 `ensureLogin()` 的跳转实现是 `router.pushUrl`。详情页第 1896 行那么用是真机验过的，但**首页那张卡片的导航壳不同**，pushUrl 在嵌套 HdsNavigation 里是否可用我无法确认——这正是你之前踩过的 push 丢失那类坑。所以要真机点一次才算数。

### 4.2 登出后仍存活的详情页保留上一账号互动态

`PostDetailView.ets:659`：

```ts
onAccountSwitch(): void {
  if (getToken() !== '') { this.load(); }   // ← 登出时 token 变空，恰好跳过
}
```

文件头注释写的是「账号切换/**登出**：重新加载本帖」，代码只做了切换那一半。NavDestination 实例不随返回销毁，所以「详情 → 设置 → 登出 → 返回到还活着的详情页」会看到上一账号的红心/已收藏/已投票仍标着。

建议补丁：去掉 `if` 无条件 `this.load()`（`load()` 本就支持匿名，详情页第 560 行不分登录态）。

配套：`utils/debateVoteStore.ets` 全站没有 `clear()`（`likeStore` 有，见 `HomeTab.ets:273`）。加一个并在 `likeStore.clear()` 的三个调用点旁边一起调。

**为什么留给你**：这条必须真机走「登出→返回」路径复现与确认，我退不了你的账号。
