## 1. 各成员核心结论

### 🔍 产品评审员（目标人群与投放目标）
- **核心判断**：每日一贴是留给"沉默大多数"的低门槛发现入口；真问题不是"排序更准"，而是在**反馈极稀疏（仅 expose/click 二值、无停留/完读）**的前提下做出不伤体验、不造茧房、可被合规审计的投放。
- **首要服务对象 = 沉默阅读型**（而非高活跃用户）：高活跃型信号足、能自我服务；沉默型才是每日一贴存在的意义与留存最大盘。
- **关键建议**：北极星指标定为**每 DAU 每日「有效阅读数」**（expose→click→互动加权，**非裸点击**）；主张**以长期留存为主目标、CTR 仅作约束**；多样性设硬下限、高曝光作者设配额。

### 🔧 工程分析员（算法设计）
- **核心判断**：个性化可在现有 Node+Prisma+MySQL 栈内实现，**无需向量库**；关键是复用 `Post.hotScore` 列而非在请求路径重算。
- **关键建议**：打分模型 `score = 1.0·tanh(hotScore/30) + 1.4·tanh(亲和/5) + 0.2·新鲜度 − 0.8·负反馈惩罚`（个性化权重高于全局热度）；把打分做成**日切纯函数**以保住"按日稳定"契约。
- **额外发现（其余成员未提）**：`dailyPostService.test.ts` 的 mock 未覆盖 `postEvent/follow/searchHistory`，**任何每日路径的新表查询都会 `prisma.xxx is undefined` 炸测试**，须以 try/catch 兜底收敛进新服务。

### ✅ 质量门神（评估与实验）
- **核心判断**：主指标当前**无法计算**——缺 `scene` 维度导致每日一贴曝光/点击不可归因。
- **关键建议**：先补最小埋点（action 扩白名单 + `scene` + `daily_open`）；首轮 A/B **只做二元对照**（现算法 vs 全量新 scorer），权重精调放后续单因子轮次；按 `userId` hash 稳定分流、游客不进实验。
- **量化结论**：基线 CTR 8%、MDE 1pp、α=0.05、power=0.8 → **约 12.2k 用户/组，14 天周期**。

### 🛡️ 安全官（合规与隐私）
- **核心判断**：功能当前**不具备上线合规条件**，存在 3 个 🔴 上架阻塞项。
- **关键建议**：①上线前完成**算法备案**（10 个工作日内，含自评估报告）；②在 `PrivacySettingsPage` 增**便捷关闭个性化推荐**开关，关闭后降级为时间/热度排序；③修复埋点（userId 回填 + postId 校验 + 防刷 + 补索引）。
- **额外发现**：`/post-event` 不校验 postId 存在性 → 可伪造刷量，命中"流量造假"条款；`SearchHistory` 为明文关键词且无 TTL，建议特征化后再建模。

## 3. 算法设计要点（回应需求五大项）

### 3.1 目标用户群体（分层与首要对象）

| 分层 | 识别规则（真实字段） | 对算法的特殊要求 |
|---|---|---|
| **沉默阅读型**（首要对象） | `PostEvent(expose)` 多但 click/互动极少，`UserFollowTag` 稀疏 | 弱信号建模、热门兜底、**禁止用稀疏点击过拟合** |
| 高活跃兴趣型 | 近 14 天 click ≥ 阈值且 `UserFollowTag` ≥ 3 | 反重复、漂移跟踪、多样性兜底 |
| 新用户/冷启动 | 注册 ≤7 天 或 `PostEvent` < 阈值 或 标签为空 | 探索优先、多样性拉满、快速采集偏好 |
| 垂直深耕型 | 单一 tag 占比 > 60% | 深挖长尾、减少无关跨域 |
| 社交关系驱动型 | `Follow` 数高、关注作者内容点击占比高 | 关系加权，但防封闭圈层 |

### 3.2 偏好特征维度与优先级

| 维度 | 数据来源 | 可信度 | 时效 | 优先级 | 现状 |
|---|---|---|---|---|---|
| 兴趣标签 | `UserFollowTag` | 高 | 长期 | **P0** | 有（仅取最近 6 个，颗粒粗） |
| 阅读历史 | `PostEvent(click)` | 中（仅二值） | 短 | **P0** | ⚠️ 有表但 **userId 恒 null + 缺索引** |
| 互动行为 | `Up`/`Bookmark`/`Comment`/`DebateVote` | 高 | 中长期 | **P0** | 有 |
| 搜索行为 | `SearchHistory` | 高 | 短 | P1 | 有但未接入投放 |
| 社交关系 | `Follow` | 中高 | 中长期 | P1 | 有但未接入 |
| 负反馈 | `Blocklist`/`Dislike` | 高 | 即时 | **P0** | 仅作者级硬排除，无内容级 |

> **需补埋点**：停留时长/完读率、滑动跳过、点击后二级行为、曝光去重、**推荐来源标记（scene）**。

### 3.3 投放目标
- **北极星**：每 DAU 每日「有效阅读数」（expose→click→互动加权）
- **一级指标**：CTR ｜ 7 日留存 ｜ 长尾内容曝光占比
- **权衡原则**：**长期留存为主目标，CTR 为约束**；多样性设硬下限，宁可牺牲 2–3% CTR。

### 3.4 个性化打分模型

```
score(post,u) = W_G·ĝ + W_A·â + W_F·f − W_P·pen
  ĝ = tanh(post.hotScore / 30)                     ← 直读列，绝不在请求路径调 computeHotScore
  â = tanh( (Σ_{t∈post.tags} w_tag(u,t) + w_author(u,authorId)) / 5 )
  f = max(0, 1 − ageHours/72)                      ← 仅"极新"短窗加成（hotScore 已含衰减）
  pen = 0.6 × 命中负反馈标签数
  w_tag(u,t) = Σ_k actionWeight_k · 0.5^(ageDays/14)   （follow=3 up=5 bookmark=6 comment=4 click=1 searchHit=2）
权重初值：W_G=1.0, W_A=1.4, W_F=0.2, W_P=0.8
```

### 3.5 三类边界场景策略

| 场景 | 策略 |
|---|---|
| **冷启动** | 新用户：`â=0` → 退化为纯热度 + 沿用热门标签兜底 + 体裁去重；新帖：每页预留 1–2 个 `<24h` 探索位；低活跃：**贝叶斯收缩** `â_eff=(n·â+m·â_pop)/(n+m)`，`m=5`。降级链：个性化 → 收缩 → 热门标签 → 全局热度 → 最新 |
| **偏好漂移** | 半衰期 **H=14 天**（近 7 天 1.0x，>30 天丢弃）；ε-greedy 探索 `ε=max(0.05, 0.15−0.02·log2(1+actionCount))`；**打分做成日切纯函数**（`asOf=当日 00:00`），ε 用 `dateKey+viewerKey` 播种、日内冻结 → 保住"按日稳定 + 跨页不重复" |
| **数据稀疏** | 标签共现矩阵（MySQL 8 `JSON_TABLE` 纯 SQL 离线统计）；轻量协同（自连接 `UserFollowTag`/`Up`，日跑预计算）；内容侧关键词兜底。**不引入向量库** |

### 3.6 效果评估指标

- **离线**：AUC / NDCG@K / Recall@K / HitRate（K=10）、Coverage、Novelty、ILD·标签熵；按**时间切分**防泄漏，负采样 1:4~1:10，control = 现 `listDailyPosts`
- **在线**：CTR、点击-互动率、人均互动数、**每日一贴打开率/渗透率**、D1/D7 留存、人均停留
- **护栏**：多样性 ILD（降幅 >15% 熔断）、热门集中度（Gini >0.7）、标签熵（降 >10%）、P95 延迟（>400ms 熔断）、崩溃率（>0.5% 立即熔断）
- **灰度**：1% → 5% → 20% → 50% → 100%，每阶段护栏全绿方可放量；回滚 = 关配置开关（回退原逻辑，**无需发版**）
